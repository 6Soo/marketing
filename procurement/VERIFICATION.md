# 검증과 재개 기록

기준일: 2026-10-21. 현재 명세는 `NARA-20261020` 버전 3입니다. 등기임원 개인회원 계정으로 회사 신규 등록을 우선하며 특정 공고 응찰은 실행하지 않습니다.

## 2026-10-21 재개

사용자가 기업금융인증서 발급 완료를 확인했습니다. 승인 범위는 1년·부가세 포함 4,400원이며 발급·수수료 승인을 다시 묻거나 재발급·중복 결제를 하지 않습니다. 실제 은행 발급 완료 화면·영수증·금융인증서 유효기간·서명은 독립 확인하지 않았으므로 사용자 확인과 구분합니다.

기존 Aside REPL 접속은 `ECONNREFUSED 127.0.0.1:21420`과 Aside 미실행 오류로 종료됐습니다. 설치된 Aside 앱을 실행해 새 REPL 세션을 연결했습니다. 열린 탭에 나라장터가 없어 공식 홈을 새로 열었습니다. 로그인이 풀려 있고 아이디·비밀번호 자동입력이 확인되지 않아 기존 등기임원 개인회원 재로그인을 사용자에게 요청하고 로그인 탭을 앞으로 가져왔습니다. 비밀번호·인증번호는 수집하지 않습니다.

정확한 재개 위치는 Aside 나라장터의 개인회원 로그인 화면입니다. 로그인 후 이용자관리 → 조달업체등록 → 입찰참가자격등록신청에서 저장된 사업자번호의 내용을 불러오고 실제 접수내역을 먼저 확인해 중복 송신을 방지합니다. 신규 송신이 필요하면 금융(사업자)인증서를 선택하고 사용자 클라우드 인증·서명을 거쳐 접수내역과 온라인 제출서류를 확인합니다. 회사 등록 승인·등록증은 아직 확인하지 못했습니다. 아래 2026-10-20 은행 발급 대기는 이력입니다.

## 버전 3 실제 신청 진행

최신 비용 승인: 사용자가 KB국민은행 기업금융인증서 1년·부가세 포함 4,400원 발급에 동의했습니다. 동일 비용과 기간을 다시 승인받지 않습니다. 기존 발급 탭에서 1년 상품 선택을 확인하고 필수 약관 보기와 약관동의 예 버튼을 조작했습니다. 전체·개별 약관 보기는 발급 첫 화면을 표시하는 별도 창으로 열렸고 원래 약관 원문은 확인하지 못했습니다. 예 버튼을 누른 뒤에도 실제 다음 단계로 이동한 화면은 확인되지 않았습니다. 원인을 확정하거나 동의·결제·발급 성공으로 기록하지 않았습니다. 점검용으로 연 두 개의 중복 창만 닫아 원래 발급 탭과 나라장터 탭을 보존했고 사용자 직접 진행과 은행 본인확인을 요청했습니다. 비밀번호·OTP·인증번호는 수집하거나 입력하지 않았습니다. 실제 수수료 출금·인증서 발급·회사 신청 송신은 미확인입니다. 아래 비용 승인 대기는 과거 이력입니다.

최신 사용자 확인: 현재 PC의 은행보험용 인증서만 보유합니다. 기존 Aside의 KB국민은행 기업금융인증서 발급 탭을 확인해 발급대상 선택·약관동의 화면에서 1년 4,400원, 2년 8,800원, 3년 13,200원(부가세 포함)을 확인했습니다. 조달청의 사업자용 금융인증서 허용 안내와 대조했습니다. 1년 상품의 신규 발급 비용 승인을 질문한 상태이며 화면의 기본 선택을 승인으로 해석하지 않았습니다. 발급 동의·결제·OTP·비밀번호 입력은 실행하지 않았습니다. 승인 뒤 선택 기간으로 진행하고 계좌 비밀번호·OTP·문자인증 단계는 사용자에게 맡깁니다.

최신 인증서 점검: 사용자가 로컬 인증서를 불러올 수 없다고 답해 공개 인증서의 회사명 일치·기간·용도 코드와 MagicLine 설치·실행·드라이브 인식 상태를 조사했습니다. 표준 폴더에는 사업자 은행보험용 코드 `1.2.410.200005.1.1.2` 한 개가 있었고, 실제 나라장터 공식 스크립트의 법인 허용 목록 50개에서 이 코드는 제외되어 있습니다. MagicLine 설치·요구 버전은 모두 1.0.0.33이며 C드라이브 인식도 확인했습니다. 앞선 업데이트 대기 기록보다 이 점검이 우선합니다. 비밀키 내용·비밀번호는 읽지 않았고 허용 목록이나 보안 설정도 변경하지 않았습니다. 별도 범용 공동인증서 또는 사업자용 금융인증서의 보유 여부·위치를 확인한 뒤 재개합니다. 상세 근거는 [인증서 점검](04-certificate-diagnosis.md)에 있습니다.

점검 후 검증: 공개 스크립트 SHA-256과 주석을 제외한 법인 허용 코드 50개, 은행용 제외·범용 및 사업자용 금융인증서 포함, MagicLine 설치·요구 버전 일치, 두 저장소 JSON 일치, 미송신·미승인 상태를 재검사해 PASS입니다. 갱신한 Excel 8개 시트·PDF 6쪽의 인증서 상태와 개인 이름·식별번호·개인전화 혼입 검사, 관련 문서 공백 검사도 통과했습니다. 문서와 로컬 환경 점검이므로 운영 앱 빌드·배포·DB 작업은 하지 않았습니다.

- 사용자 답변과 실제 화면으로 개인회원 가입·로그인 완료를 확인했습니다. 로그인 계정은 등기임원입니다. 대표자정보의 신청자본인은 선택하지 않고 현재 사업자등록증의 대표자를 별도 입력했습니다. 이 최신 확인이 과거 대표자 본인 신청·개인회원 미가입 기록보다 우선합니다.
- 기존 사업자번호의 임시저장 신청서를 불러와 회사 대표전화, 상세주소, 홈페이지, 법인설립일 2019-08-30, 본점소재지등기일 2026-09-16을 보완했습니다. 기존 종업원수 2는 사용자 입력을 보존했으며 상시근로자 2명으로 재해석하지 않았습니다.
- 보안 원본에서 대표자 필수정보를 직접 입력했습니다. 비공개 값은 Git과 보고서에 쓰지 않았습니다. 실명확인의 보안문자는 사용자가 직접 처리했고, 이후 성명·주민번호·실명인증 버튼이 비활성화된 것을 확인했습니다.
- 실제 업종 검색에서 국내외여행업 1262를 확인해 한 건만 추가했습니다. 면허번호 입력 창에서 서울강서와 2026-000025를 입력해 서울강서제2026-000025호가 만들어졌습니다. 현재 강서구 등록증 DOC-07의 날짜 2026-09-23을 입력했습니다. 최초 여행업 등록일로 확정하지 않았으며 유효기간·시공능력평가액은 만들지 않았습니다.
- 서울 본점 관할인 서울지방조달청을 선택하고 담당자 회사 전화·업무 이메일과 등기임원 역할을 반영했습니다. 신청 목적의 행정정보 공동이용과 청렴계약 내용을 읽고 동의했습니다. 임시저장 성공 메시지를 확인한 뒤 다시 불러와 회사 기본정보 다섯 항목, 대표자 이름·이메일·전화, 업종·번호·등록일, 접수기관과 담당자정보가 유지됐는지 값 비교로 검증했습니다.
- 송신 검증에서 요구한 법인번호 중복조회 결과는 0건, 회사 전화번호는 등록 가능한 번호였습니다. 송신 확인에 예를 눌러 공동인증서 선택 창에 도달했습니다. 하드디스크 사용을 선택하자 MagicLine 최신 버전 설치 안내가 나왔습니다. 사용자 설치·인증서 선택·비밀번호 입력·전자서명만 대기합니다. 실제 송신 완료·접수번호·승인·등록증은 아직 확인하지 못했습니다.
- 정확한 재개 위치는 Aside 나라장터 탭의 MagicLine 설치 안내와 인증서 선택 창입니다. 사용자 전자서명 후 성공 화면 또는 오류를 확인하고 접수내역과 제출서류를 확인합니다. 인증서 파일·비밀번호·보안문자를 채팅으로 받지 않습니다. 자동 유지나 자동 재개를 보장하지 않습니다.
- 현재 신청 상태를 반영해 Excel·PDF·요약 이미지를 다시 생성했습니다. 생성 검증 PASS, Excel 8개 시트와 PDF 6쪽을 확인했고 요약 이미지를 직접 검토했습니다. 두 저장소 회사정보 JSON의 바이트 일치, 저장 완료·실명확인 완료·미송신·미승인 상태, 신청 역할, 개인 이름·식별번호·개인전화의 산출물 혼입 여부 검사 PASS입니다. 문서 변경이므로 운영 코드 빌드·DB·배포·서버 재시작은 실행하지 않았습니다.

## 후속 브라우저 실행

사용자가 새 Aside REPL에서 나머지 작업을 진행하도록 지시했습니다. 새 브라우저에는 기존 입력이나 로그인 상태가 보이지 않았습니다. 나라장터 홈 → 로그인 → 신규 이용자 등록에서 업체 탭이 비활성화된 것을 실제 화면 요소에서 확인했습니다. 비활성화를 우회하지 않고 개인회원 가입으로 진행했습니다.

필수 개인정보 수집·이용 내용을 확인한 뒤 필수 동의만 선택하고 계속진행을 눌렀습니다. 선택 동의는 비동의 상태로 유지했습니다. 회원가입 화면의 이름·아이디·비밀번호·휴대전화·이메일 입력란은 본인 인증 전 비활성화돼 있었습니다. 본인확인을 눌러 NICE·금융인증서·카카오뱅크 선택 팝업을 열고 `page.bringToFront()`로 나라장터 탭을 앞으로 가져왔습니다.

대표자 본인 인증이 필요한 지점에서 멈추고 채팅으로 직접 인증을 요청했습니다. 인증번호·비밀번호는 수집하거나 입력하지 않았고, 회원가입 저장·회사 등록 송신·승인은 아직 실행하지 않았습니다. 다음 작업은 본인 인증 완료 여부를 확인한 뒤 활성화된 입력란을 채우는 것입니다. Aside REPL은 임시 세션이므로 다음 실행에서는 기존 탭 존재부터 확인하고, 자동 유지나 자동 재개를 보장하지 않습니다.

이하 버전 1의 조사·검증 기록은 이력입니다. 버전 2와 후속 브라우저 실행의 확인 사실과 실행 범위가 우선합니다.

## 실제 확인

- 사용자 확인: 회사의 나라장터 등록은 아직 하지 않았습니다.
- marketing 작업 기준과 origin/main은 `e5751d1`, foresttour 작업 기준은 `29496ba`, 원격 인계 기준은 `3d7b81b`입니다. 두 저장소 모두 기존 사용자 변경이 있어 pull·checkout을 하지 않고 fetch·git show로 대조했습니다.
- 원격 인계서 제6절은 조사 요청과 결과 미확인을 기록합니다. 과거 보고서를 복원했다는 주장은 하지 않습니다.
- 웹 조사는 공식 조달청·정부24·SMINFO를 사용했습니다. 웹 브라우저 확인은 **Aside REPL**로 했습니다. Paseo 브라우저 도구는 사용하지 않았습니다.
- 나라장터 개인회원·조달업체 안내, 신규이용자등록, 로그인 화면을 확인했습니다. 개인 인증을 요구하는 단계에서 추가 실행하지 않았습니다. 회사 등록 폼의 로그인 이후 입력·저장·전송은 미실행입니다.
- 서울고 공식 상세를 직접 조회했고 공고 PDF와 과업 HWP를 HTTP 200으로 내려받았습니다. PDF는 16쪽이며 과업 HWP는 BodyText 레코드를 추출했습니다. 공식 원문과 상세의 시각·기간·보증 문구 충돌을 기록했습니다. 원문 HWP 표의 화면 배치를 재현했다고 주장하지 않습니다.
- 공개 근거 원본은 `evidence/raw/`에 로컬 보관합니다. 파일별 SHA-256과 크기는 [manifest.json](evidence/manifest.json)에 있습니다. 원본은 Git 제외를 확인했습니다. 회사 증명서·고객 개인정보 원본을 복제하지 않았습니다.

## 산출물 검사

- 생성 명령: `python procurement/build-preparation.py`.
- Excel: 8개 시트, 알려진 회사 정보와 미확인 칸 분리, 원가·누적자금·평가 수식 및 입력 범위 검사.
- 값이 없는 비용을 자동으로 0원 처리하지 않습니다. 비용 전체 합계는 모든 항목의 숫자 입력이 있어야 나타납니다. 미사용 항목은 명시적으로 0을 입력하도록 설명했습니다.
- 평가의 실제 점수는 비워 두고, 최저 구간 가정 예시의 합계 `2+2+2+0+70=76<80`을 별도로 확인했습니다. 실제 회사 점수로 확정하지 않았습니다.
- Excel 앱에서 직접 계산·실행한 검증은 아닙니다. 수식 구조와 참조를 검사했고, 파일을 열 때 재계산하도록 설정했습니다. 견적·자금·보유 실적의 실제 값은 아직 없습니다.
- PDF: 6쪽 생성, 각 페이지 텍스트 추출과 인쇄 영역 안 배치 검사. 요약 PNG를 직접 열어 한글·표·가독성을 확인했습니다.
- Aside는 로컬 파일 열기 권한을 제공하지 않아 로컬 HTML 열기에 실패했습니다. 그 제한을 변경하지 않고 **브라우저가 아닌 PyMuPDF 문서 렌더러**로 PDF·PNG를 생성했습니다.
- 생성 과정에서 표의 첫 열이 너무 좁게 배치된 문제를 발견해 열 너비를 명시하고 다시 렌더링했습니다. 실패한 중간 출력은 최종 산출물로 전달하지 않습니다.
- 문서 상대 링크·JSON·허용 문자·Git 공백 검사와 원본 제외를 확인합니다. 운영 코드·DB 변경이 없어 앱 빌드·운영 회귀·배포·서버 재시작은 하지 않습니다.

## 위임과 검토

foresttour 지침의 독립 자료 점검에 Paseo 스킬을 적용했습니다. 명명된 프로필은 없었고 승인된 무료 후보 순서에서 Muse와 Space Bunny가 각각 실제 410 폐기 오류로 실패해 Inkling Small로 전환했습니다. 앞선 실패를 같은 모델로 반복하지 않았습니다. 전달 범위는 회사 증빙 읽기와 단일 초안 파일뿐이었습니다.

보조 초안의 경로·상태 인용 오류를 주 작업자가 실제 파일·원격 원문과 대조해 발견했습니다. 보조 결과를 통과 증거로 사용하지 않고 [회사 증빙 점검](company-evidence-audit-2026-10-20.md)을 확인된 사실 중심으로 다시 썼습니다. 별도 임시 worktree를 만들지 않았습니다.
