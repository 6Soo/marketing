# 인스타 자동 게시 + 음악 — 시스템 설계와 사실관계 (2026-07-21)

> 발단: "카드뉴스 자동화는 됐는데 음악이 안 들어간다"(유튜버 사례). 조사 결과 이것은
> 구현 실수가 아니라 **플랫폼 사양**이다. 이 문서는 그 근거와 우리 해법의 기록.
> 공식 문서 교차 검증 완료(근거 URL은 말미).

## 1. 왜 '캐러셀 + 음악' 자동화는 아무도 못 하나 (사실관계)

1. **게시 API에 음악 파라미터가 없다.** 사진(IMAGE)·캐러셀(CAROUSEL)·스토리 컨테이너의
   파라미터 전수 확인 — 오디오 관련 항목 전무. 음악 스티커·음악 라이브러리는 **앱 전용 기능**.
2. **`audio_name`은 함정.** 릴스(REELS) 전용 파라미터인데, 라이브러리에서 곡을 고르는 게 아니라
   **영상에 이미 들어 있는 '원본 오디오'의 표시 이름**을 정하는 것뿐이다(1회 변경 가능).
3. **게시 후 앱에서 음악만 얹는 하이브리드도 불가.** 이미 게시된 게시물에 음악 추가/교체 기능
   없음(라이선스가 업로드 시점 단위로 묶임). 삭제 후 재게시(반응 소실)뿐.
4. **서드파티도 똑같다.** Buffer 공식 헬프: "Due to API limitations, Buffer is not able to add
   trending music to posts or reels." — 같은 Graph API를 쓰는 모든 도구의 공통 한계.

## 2. 우리 해법 — 이원 파이프라인 (같은 카드 소스, 두 출구)

```
cards.mjs (카드 데이터, 시리즈당 1개)
  ├─ render.mjs      → 1080×1350 PNG 9~11장 ──[JPEG 변환]──→ 캐러셀 게시 (무음 · 저장용)
  └─ build-reel.mjs  → 1080×1920 MP4 (H.264+AAC, 카드당 3.2s 슬라이드,
                        음악을 오디오 트랙으로 구워 넣음) ──→ 릴스 게시 (음악 · 도달용)
```

> ⚠ **JPEG 변환 필수 (2026-07-23 공식 문서 실측 정정)**: Content Publishing API는 **JPEG만** 받는다
> ("JPEG is the only image format supported"). render.mjs 산출물은 PNG이므로 게시 전 반드시 JPEG로
> 변환해 공개 URL로 올려야 한다(PNG URL로 게시하면 실패). 변환·업로드·게시를 한 번에 묶는 러너는
> `cardnews/tools/daily-publish.mjs`(아래 §7).

- **캐러셀(무음)은 결함이 아니라 사양** — 저장·정독용. 학습-09: 캐러셀 저장률이 핵심 지표.
- **음악이 필요한 노출은 릴스가 담당** — API 게시에서 음악이 살아남는 유일한 경로는
  "영상 파일에 구워 넣은 오디오"다. `share_to_feed=true`(기본값)면 피드에도 함께 노출.
- 게시 모듈: `tools/instagram-publish.mjs` (carousel/reel/refresh-token/limit, 기본 드라이런,
  `--publish`로 실전송). 기본 호스트는 2024-07 신설 **Instagram API with Instagram Login**
  (graph.instagram.com — **페이스북 페이지 연결 불필요**).

## 3. 음원 전략 (저작권 — 여기서 틀리면 음소거·차단)

- 비즈니스 계정은 앱에서도 상업 음원 라이브러리가 막혀 있다(개인·비상업 한정 라이선스).
  무단 상업 음원을 영상에 구워 넣으면 Meta Music Guidelines에 따라 **차단·음소거·삭제** 가능.
- **1순위: Meta Sound Collection**(facebook.com/sound/collection) — 약관 원문상 다운로드→영상
  삽입→인스타/페북 게시가 **상업 목적 포함 명시 허용**. ⚠ 단 **Meta 플랫폼 외부 사용 금지**
  — 같은 영상을 유튜브에 올리려면 그 판은 별도 음원(구매 로열티프리)으로 다시 구워야 한다.
- **현재 상태**: `cardnews/assets/music/placeholder-ambient.wav` — 코드로 합성한 자작 앰비언트
  (gen-music.mjs, 저작권 원천 청정)라 그대로 게시해도 법적 문제는 없다. 다만 완성도는
  Sound Collection 트랙이 나으므로 실게시 전 교체 권장(사장님-가이드 §9-7).

### 3-A. 무료 상업용 음원 폭넓은 검토 (2026-07-29 추가 조사)

**결론부터: 인스타 전용이면 Meta Sound Collection, 인스타+유튜브 양쪽에 같은 판을 쓰려면 Pixabay.**

| 출처 | 상업 사용 | 출처 표기 | 플랫폼 제약 | 판단 |
|---|---|---|---|---|
| **Meta Sound Collection** | 허용(명시) | 불필요 | **Meta 플랫폼 전용** — 유튜브 사용 금지 | 인스타 전용 판의 1순위 |
| **Pixabay Music** | 허용 | **불필요** | 없음 — 인스타·유튜브 모두 가능 | 교차 게시의 1순위 |
| **YouTube 오디오 보관함** | 조건부 | 트랙별 | ⚠ **표준 라이선스는 유튜브 전용** | **인스타에 쓰면 약관 위반** |
| 인스타 인앱 음악 라이브러리 | ✗ | — | 비즈니스 계정은 상업 사용 불가 | 애초에 API 게시 불가 |
| Bensound·셀바이뮤직·프리뮤직 등 | 트랙별 상이 | 트랙별 | 트랙별 | 개별 확인 필수 — 일괄 신뢰 금지 |

**⚠ 정정**: 이전에 "무료 옵션(유튜브 오디오 보관함 등)부터 검토"라고 권한 적이 있는데 **틀렸다.**
오디오 보관함 표준 라이선스는 **유튜브 영상에만** 허용되며, 인스타·웹·팟캐스트에 쓰면 약관 위반이다.
예외는 CC-BY 트랙뿐이고 그 경우 **출처 표기가 의무**다.

**Pixabay를 교차 게시 1순위로 두는 이유**: 라이선스가 "취소 불가·전 세계·비독점·로열티프리"이며
상업 사용을 허용하고 **출처 표기를 요구하지 않는다.** 이 문서 §3이 지적한 "같은 영상을 유튜브에
올리려면 음원을 갈아 다시 구워야 한다"는 이중 작업이 Pixabay를 쓰면 사라진다.
숲길여행은 유튜브 채널도 예정돼 있으므로(video/ SOP) 한 번만 굽는 편이 낫다.

**단, Pixabay의 위험은 라이선스 조항이 아니라 업로드 출처다.** 사용자 업로드 기반이라
업로더가 권리 없는 음원을 올렸을 가능성이 구조적으로 존재한다. 반면 Meta Sound Collection은
Meta가 자사 플랫폼용으로 직접 확보한 것이라 인스타에서만큼은 더 안전하다.

**운영 권장**: 인스타 릴스만 낼 때는 Meta Sound Collection, 같은 영상을 유튜브에도 낼 때는
Pixabay. 어느 쪽이든 **다운로드 시점의 트랙 페이지·라이선스 문구를 캡처해 보관**한다
(사진 출처 검증과 동일한 원칙 — 나중에 증명할 수 없으면 쓰지 않은 것과 같다).

**공통 주의**: 상업 주체를 홍보하는 콘텐츠는 계정 유형과 무관하게 상업 라이선스가 필요하다.
비즈니스 계정이 인앱 인기 음원을 쓰면 차단·음소거 대상이다.

## 4. 릴스 규격 체크리스트 (build-reel.mjs 산출물이 전부 충족)

| 항목 | 공식 사양 | 우리 산출물 |
|---|---|---|
| 컨테이너 | MP4/MOV, moov 앞쪽 | MP4 + faststart ✓ |
| 비디오 | H.264/HEVC, 4:2:0, ≤가로 1920px | H.264 High, yuv420p, 1080×1920 ✓ |
| 오디오 | AAC ≤48kHz ≤128kbps | AAC 44.1kHz 128k ✓ |
| 비율·길이 | 9:16 권장, 3초~15분 | 9:16, 28.8초 ✓ |
| 프레임 | 23~60fps | 30fps ✓ |
| 크기 | ≤300MB | 약 3MB ✓ |

## 5. 운영 수칙

- **게시 한도**: 24시간 이동 창 기준 API 게시 100회(캐러셀=1회). 확인: `limit` 커맨드.
- **캐러셀은 API로 최대 10장**(앱은 20장) — 우리 표준 9장이라 여유 있음.
- **토큰은 60일 시한부** — 만료 전 `refresh-token --write-env`로 갱신한다.
  새 토큰의 계정 ID가 기존 `IG_USER_ID`와 일치하는지 먼저 확인한 뒤 저장한다.
  토큰은 화면·Actions 로그·Graph URL에 출력하지 않고 로컬 `.env`의 해당 값만 교체한다.
  잊으면 만료 후 재발급해야 하므로, 월 1회 갱신을 루틴에 넣는 것을 권장.
- **미디어는 공개 URL 필수**(Graph API가 URL에서 받아감) — 후보: reserve.foresttour.kr의
  정적 폴더(reservation 리포 public/). 다음 단계에서 reservation 리포와 함께 자동화.
- 앱 리뷰 불필요: 자기 계정만 쓰는 앱은 개발 모드 + Standard Access로 충분.

## 6. 남은 일 (사람 몫 — 상세 절차는 context/사장님-가이드.md §9)

## 7. 일일 자동발행 러너 · 크론 (2026-07-23 신설)

한 장짜리 오케스트레이터 `cardnews/tools/daily-publish.mjs`가 아래를 한 번에 묶는다(기본 드라이런):

```
render.mjs(PNG) → JPEG 변환 → 공개 폴더(PUBLIC_DIR) 스테이징 → instagram-publish.mjs carousel
```
- 표지 후보(cover-a/b/c) 중 1장 + 내지 전부를 순서대로 골라 최대 10장까지 게시(초과 시 앞 10장).
- 캡션은 시리즈 폴더의 `캡션.md`(또는 caption.txt)를 그대로 사용 — 이 파일이 **최종 캡션 텍스트**여야 함.
- 변환기 자동탐색: `sharp`(권장, CI에 `npm i sharp`) → ImageMagick → ffmpeg → python Pillow.
- 사용:
  ```
  node cardnews/tools/daily-publish.mjs --series=cardnews/series/sanriku            # 드라이런
  node cardnews/tools/daily-publish.mjs --series=cardnews/series/sanriku --publish  # 실게시
  ```
- GitHub Actions: `.github/workflows/daily-cardnews.yml`을 수동 실행한다.
  `step=publish`, `series=<시리즈 경로>`, `publish_live=true`일 때만 실제 게시한다.
- 공개 JPEG는 전용 `instagram-assets` 브랜치에 실행별 폴더로 배포한다. 게시에는 브랜치명이 아니라
  배포 커밋 SHA가 들어간 `raw.githubusercontent.com` 고정 URL을 사용해 캐시 충돌을 막는다.
- 워크플로 순서:
  `실게시 안전검사 → PNG 렌더 → JPEG 스테이징 → 자산 브랜치 푸시 → 공개 JPEG 전수 검증 → 중복 확인 → API 게시`.
- 공개 JPEG는 첫 장만 확인하지 않는다. 2~10장 모두 HTTP 200·`image/jpeg`·JPEG 매직바이트·
  최소 크기·로컬 SHA-256 일치를 통과해야 한다.
- 캡션과 게시 JPEG 바이트로 SHA-256 콘텐츠 지문을 만들고 manifest와 게시 결과에 남긴다.
  실게시 직전 최근 미디어 25개의 캡션을 조회해 같은 캡션이 있으면 중복 게시를 차단한다.
- 게시 성공 시 `media_id`·permalink·게시 시각을 `instagram-publish-result-<run_id>` 아티팩트로
  90일 보존한다. 기록에는 콘텐츠 지문도 포함하며, 게시물별 Insights와 연결해 저장률·공유율을 계산한다.
- 필요한 GitHub Secrets는 `IG_USER_ID`, `IG_ACCESS_TOKEN` 두 개다. 공개 URL은 워크플로가 계산하므로
  `PUBLIC_BASE_URL` Secret과 별도 Vercel/S3 배포는 필요 없다.
- `photoStatus !== verified`인 시리즈는 워크플로에서 예외 없이 차단한다. 대역 사진 우회 옵션은
  로컬 진단용 CLI에만 남고 운영 워크플로에는 노출하지 않는다.
- 예약 실행은 3회 수동 실게시 검수 후 별도로 복구한다.
- ⚠ **타이밍 불변식**: 이미지는 발행 호출 **전에** 공개 URL로 라이브여야 한다. 워크플로는 모든 JPEG를
  실제 HTTP GET으로 내려받아 로컬 스테이징 바이트와 동일한지 확인한 뒤에만 Instagram API를 호출한다.
- ※ 음악이 훅에 필수인지(왜 무음 캐러셀이 저장 전략에 맞는지)의 통계 근거: `learning/학습-10-릴스vs캐러셀-음악-저장전략.md`.
