# 사장님 가이드 — 숲길여행 시스템 사용·운영 통합판

> 최종 개편: 2026-07-05 (2판) · **사람이 할 일은 전부 여기에만** 있습니다.
> (05~08번 문서는 "무엇을 왜 만들었나"의 기록용)

## 우리의 원칙 — 이사가 아니라 도움·개선·아름다워짐

**근간은 카페(cafe.foresttour.kr)입니다. 회원을 어디로도 옮기지 않습니다.**
시스템이 하는 일은 세 가지뿐입니다:
1. 회원이 **카페에 올라온 여행**을 쉽게 보고, 쉽게 예약하도록 돕는다
2. **대장**이 수기 명단·카톡 관리보다 편하게 일하게 한다
3. **카페 자체**를 아름답고 편하게 만든다

도메인 정리 (2026-07-22 갱신):
- `foresttour.kr`(루트) = **2030 신규 유입용 새 홈** (인스타·유튜브 착륙지, 이 리포가 만드는 콘텐츠의 목적지)
- `cafe.foresttour.kr` = **카페** (다음카페로 302 리다이렉트)
- `reserve.foresttour.kr` = **예약 도우미** (이 시스템, 이미 연결·운영 중)

## 0. 시스템 지도 (1분)

**한 개의 웹앱(reservation, main 푸시 = Vercel 자동 배포)** 안에 전부 있습니다:

| 주소 | 화면 | 누가 |
|---|---|---|
| `reserve.foresttour.kr` | **여행 구경 홈** — 모집 중인 여행 한눈에 + 이번 주 신규 (R16) | 회원 |
| `reserve.foresttour.kr/reserve` | **예약 폼** (3분) — 상세에서 '이 여행 예약하기'로 진입 | 회원 |
| `reserve.foresttour.kr/tour/게시판ID` | **카페 글 큰 글씨로 보기** (원본·댓글은 카페) | 회원 |
| `reserve.foresttour.kr/admin` | **관리자** — 출발게이트·입금대사·접수·투어관리+더보기 | 사장님만 |
| `reserve.foresttour.kr/admin/traffic` | **방문 통계** — 배너·공지 유입과 예약 완료(최근 14일) | 사장님만 |
| `reserve.foresttour.kr/leader/토큰` | **대장 포털** — 명단·체크인·손님등록·입금(조회만)·안내문 | 대장 |

곁가지: **알림톡**(접수 확인·출발 D-3·귀국 D+2 자동 / 잔금 안내는 보류 §4),
**travel_ins**(보험), **cost**(장부), **interview**(채용), **flight_prep**(발권).

권한 원칙: ① 입금 상태 변경은 admin(사장님)만 — 대장은 조회만
② 주민번호는 저장 즉시 암호화, 대장 화면에 절대 재표시 안 됨.

## 2. 실운영 스위치 — Vercel 키 5개 (15분) ★가장 중요★

`npm run keys` 실행 → 키 5개 출력.
⚠️ **PII_KEY는 종이에 적어 금고 보관**(분실 시 암호화 주민번호 복구 불가).
⚠️ 재실행하면 새 값 — 이미 등록한 키를 덮어쓰지 마세요.

vercel.com → **reservation** → **Settings → Environment Variables** → 5개 등록:

| Key | 역할 |
|---|---|
| `PII_KEY` | 주민번호 암호화 (★종이 보관) |
| `ADMIN_KEY` | 관리자 비밀번호 (노출 우려로 교체) |
| `LEADER_LINK_SECRET` | 대장 링크 서명 |
| `INTERNAL_API_TOKEN` | 보험 자동화 연동 (§6 재사용) |
| `CRON_SECRET` | 새벽 자동 작업 보호 |

선택: `OFFICE_PHONE` = 대표 문의 번호 (큰글씨 글 보기 화면의 전화 버튼 — 미설정 시 숨김).

**적용:** Deployments → 맨 위 **⋯ → Redeploy**. (`TURSO_*`, `BLOB_*`는 절대 건드리지 말 것)

**확인:** `/admin` 새 비밀번호 로그인 · 기존 명단 그대로(평문 주민번호는 첫 접속 때
자동 암호화) · **대장 링크 전부 재발급**(admin → 투어 관리에서 복사, 대장에게 1:1).

**빌드 실패 시:** 로그 맨 위 `Commit:` 해시를 저에게 — 과거 커밋의 실패 로그가
뒤늦게 보이는 경우가 있으니 항상 최신 배포 기준으로.

## 4. 알림톡 (기존 승인 템플릿 재사용 — 심사는 신규 2종만)

**기존 것 그대로 씁니다.** 이미 심사 통과한 고객용(예약확정_고객)·대장용
(예약접수_담당자) 템플릿은 코드가 보내는 변수와 완전히 일치하므로 재등록·재심사
없이 **템플릿 ID만** 등록하면 됩니다. (만약 승인이 솔라피가 아닌 다른 곳이었다면
같은 문안을 솔라피에 등록 — 이미 통과한 문안이라 빠르게 승인됩니다)

**잔금 안내(D-14)는 보류** — 독촉하는 느낌이라는 사장님 결정. 발송이 기본으로
꺼져 있고 템플릿 등록도 필요 없습니다. 나중에 켜려면: 템플릿 등록 +
`SOLAPI_TEMPLATE_BALANCE` + `LIFECYCLE_BALANCE_ENABLED=1` 등록 → Redeploy →
`/api/notify-lifecycle?dry=1`로 대상 확인.

**신규 등록이 필요한 것은 2종뿐** — 출발 안내(D-3)·귀국 감사(D+2).
문안은 기존 승인 템플릿과 같은 말투(🌲 이모지·구분선·시그니처)로
`reservation/docs/alimtalk-templates.md`에 준비돼 있습니다. 그대로 복사해
솔라피 템플릿 심사에 제출하세요. (출발 안내의 `#{집결안내}`에는 대장이
포털 '안내문' 탭에 쓴 글이 자동으로 들어갑니다)

**솔라피 준비(처음이면):** solapi.com 가입(사업자) → 발신번호 등록·인증 →
카카오 채널 연동(pfId) → API Key/Secret 발급.

**Vercel 등록 (§2와 같은 방법) → Redeploy:**

| Key | 값 |
|---|---|
| `SOLAPI_API_KEY` / `SOLAPI_API_SECRET` | API 키 관리에서 발급 |
| `SOLAPI_PFID` | 채널 연동 시 발급 |
| `SOLAPI_SENDER` | 발신 전화번호 (숫자만) |
| `SOLAPI_TEMPLATE_CUSTOMER` | **기존** 고객용 템플릿 ID |
| `SOLAPI_TEMPLATE_CAPTAIN` | **기존** 대장용 템플릿 ID |
| `SOLAPI_TEMPLATE_DEPART` | 신규 출발 안내 ID (승인 후) |
| `SOLAPI_TEMPLATE_RETURN` | 신규 귀국 감사 ID (승인 후) |

### 대장이 스스로 자기 여행 관리에 들어가게 하기 (링크 안 보내도 됨)
대장 관리에서 각 대장의 **실명 + 주민번호 13자리**를 등록해 두면(🔑 표시),
대장이 `reserve.foresttour.kr`에서 예약처럼 **이름과 주민번호만 입력**해도
"○○대장님이시군요!" 하고 **본인이 맡은 여행의 명단 관리 화면**으로 바로 들어갑니다.
사장님이 매번 대장 링크를 카톡으로 보내지 않아도 됩니다.
- 주민번호는 **암호화 해시로만** 저장되고 화면에 다시 보이지 않습니다(대조용).
- 대장은 여전히 **입금 조회만** 가능합니다(변경은 사장님 admin 전용, 그대로).
- 실명·주민번호를 등록하지 않은 대장은 예전처럼 링크를 전달해 쓰면 됩니다.

## 8-2. 운영 데이터베이스(Turso) 직접 관리

일상 관리는 admin 화면이면 충분하지만, 터미널에서 전체를 빠르게 조회·백업하고
싶을 때(그리고 저에게 맡기실 때)를 위한 도구입니다.

**연결(1회):** `.env.local`에 두 줄 추가 —
```
TURSO_DATABASE_URL=libsql://<우리-DB>.turso.io
TURSO_AUTH_TOKEN=<접속 토큰>
```
값은 **Vercel → reservation → Settings → Environment Variables**에서 복사하거나,
Turso 대시보드에서 발급합니다. **조회만 할 거면 '읽기 전용(read-only)' 토큰**을
권합니다(사고 시 피해 최소화).

**사용:**
```
npm run db guides        대장 명부 — 실명·연락처·주민번호(🔑)·상태
npm run db tours         투어 목록 + 예약 인원
npm run db reservations  입금 상태별 예약 집계
npm run db stats         전체 카운트
npm run db health        스키마 점검
npm run db backup        전체 백업을 data/ 폴더에 저장(개인정보 포함 — 공유 금지)
```
- 주민번호·여권 **원문은 절대 출력되지 않습니다**(등록 여부만 🔑로 표시).
- **수정·삭제는 이 도구에 없습니다** — 데이터 변경은 기록이 남는 admin 화면에서만.
- `.env.local`과 백업 파일은 git에 올라가지 않습니다(자동 제외).

## 10. 인스타그램 자동 게시 준비 (1회, 약 30분)

> 목적: 카드뉴스를 API로 자동 게시 — 캐러셀(사진 묶음)과 릴스(음악 입힌 영상) 두 갈래.
> 음악은 인스타 사양상 캐러셀에 못 붙고 릴스 영상에 구워 넣는 방식입니다(왜 그런지:
> cardnews/docs/인스타-자동게시-음악.md). 아래만 해 주시면 나머지는 자동입니다.

### 10-1. 인스타 계정을 프로페셔널로 전환 (폰, 5분)
1. 인스타그램 앱 → 프로필 → 오른쪽 위 **≡** → **설정 및 활동**
2. **계정 유형 및 도구** → **프로페셔널 계정으로 전환** → 유형은 **비즈니스** 선택
3. 카테고리는 "여행사" 선택, 연락처는 recruit@foresttour.kr

### 10-2. Meta 개발자 앱 만들기 + 토큰 발급 (PC, 15분)
1. developers.facebook.com 접속 → 페이스북 계정으로 로그인 → **My Apps** → **Create App**
2. 용도는 **Other** → 앱 유형 **Business** → 앱 이름 "숲길 인스타 게시" → 생성
3. 대시보드에서 제품 추가: **Instagram** 찾아 **Set up**
4. 왼쪽 메뉴 **Instagram > API setup with Instagram login** 선택
   (⚠ 페이스북 페이지 연결이 **필요 없는** 신형 방식입니다 — Facebook Login 쪽 아님)
5. **1. Generate access tokens** 단계에서 **Add account** → 위 10-1의 인스타 계정으로 로그인·허용
6. 계정 옆 **Generate token** 클릭 → 나온 **토큰**과 **Instagram account ID** 둘 다 복사
   (토큰은 60일 유효 — 만료 전 갱신은 아래 10-5)

### 10-3. 키 저장 (PC, 2분)
marketing 리포 루트의 `.env` 파일에 두 줄 추가(펙셀스 키 아랫줄):
```
IG_USER_ID=복사한 Instagram account ID
IG_ACCESS_TOKEN=복사한 토큰
```

### 10-4. 배경음악 준비 (PC, 5분)
1. facebook.com/sound/collection 접속(페이스북 로그인) → 장르 "Ambient" 등에서 잔잔한 곡 시청
2. 마음에 드는 곡 **다운로드** → 파일을 리포 `cardnews/assets/music/` 폴더에 넣기
3. Claude에게 "릴스 음악을 방금 넣은 곡으로 교체해줘"라고 하시면 됩니다
   (※ 이 음원은 인스타·페북 전용 라이선스 — 유튜브에 올릴 영상에는 쓰면 안 됩니다.
   지금은 임시로 자작 합성곡이 들어 있어 그대로 테스트하셔도 안전합니다.)
