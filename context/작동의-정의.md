> 판단 기준을 줘야 겉만 그럴듯한 결과물(껍데기)을 스스로 걸러낼 수 있다.

## 1. 영역별 "작동한다"의 정의

### 예약 (돈·손님 직결 — 가장 엄격)
- 회원이 제출한 신청은 **저장되거나, 안 됐다고 화면에 분명히 보이거나** 둘 중 하나다.
  조용한 유실이 최악의 실패다.
- 마감·정원 초과 여행의 신청은 DB에 들어가지 못한다 — 동시에 여러 명이 눌러도.
- 저장 실패는 **사장에게 문자로 즉시 알린다**(같은 종류 30분 1건 스로틀). 회원 전화로
  장애를 알게 되는 구조를 없애기 위함. → `src/lib/adminAlert.ts`
- 빈/불량 입력은 400으로 거절된다 — 스모크가 이걸로 "검증하며 살아 있음"을 확인한다.

### 카페 읽기 (목록·리더·인기)
- 다음카페가 느리거나 막혀도 **화면은 죽지 않는다** — 캐시(묵은 것 포함)로 응답하고,
  파싱이 실패하면 빈 화면이 아니라 **카페 원문 링크로 폴백**한다.
- 카페 접속 실패는 '경고'다(다음의 일시 차단이 잦음). DB 실패는 '장애'다.

### 입금·PII (불변식 — 창의성 금지 구역)
- 입금 상태 변경은 admin(사장)만. 대장 포털은 조회만.
- 주민번호·여권은 enc:v1: 암호화로만 저장, 대장 화면에 원문 재표시 금지.
- 이 구역은 CLAUDE.md 불변식이 우선하며, 어떤 개선 제안도 불변식을 넘지 못한다.

### 알림 (알림톡·문자)
- 알림 실패는 예약을 실패시키지 않는다(비치명) — 단 로그에 남아야 한다.
- 잔금 독촉성 알림은 사장 결정으로 보류 — LIFECYCLE_BALANCE_ENABLED로만 재활성화.

### 계측 (visit_stats)
- 계측은 **무해해야 한다** — 어떤 화면도 track 실패로 죽지 않는다. 숫자가 비는 것은
  허용, 화면이 깨지는 것은 불허.

## 2. 자동 감시 체계 (2026-07-17 구축)

| 감시 | 주기 | 실패 시 |
|---|---|---|
| 스모크 9항목(홈·폼·목록·리더·예약검증·DB·환경변수·카페·인기) `scripts/smoke.mjs` | 6시간마다 + 배포 직후 (GitHub Actions) | **GitHub이 사장 메일로 자동 통지** |
| 단위 테스트 14건(카페 파서·뷰) `npm test` | 코드 푸시마다 | 위와 동일 |
| 예약 저장 실패 | 실시간 | **사장 휴대폰 문자** (30분 스로틀) |
| 셀프 진단 `reserve.foresttour.kr/api/health` | 수동 | 어느 구간(DB/카페/환경변수)이 죽었는지 JSON으로 표시 |

## 3. 창의성 다이얼 (AI 작업 시 참조)

- **원칙 고정(창의성 = 장애)**: 입금·PII·권한, 카드 xls 파서 규격, 예약 검증 로직,
  법령 용어. 여기서는 기존 패턴을 벗어나지 않는다.
- **창의 자유(실패가 싸고 즉시 보임)**: 화면·문구·배너·기획·모객글. 여기서는 자유
  안을 만들어 제시하되, CLAUDE.md의 톤 원칙(변화를 팔지 않는다 등)이 분별 기준.
- **중간(자율 판단 + 엄격한 경계)**: admin 기능, 자동화 스크립트 — 새 구조 제안은
  환영하되 되돌리기 쉬운 스위치(env 토글, 원복 용이 설계)를 함께 만든다.
