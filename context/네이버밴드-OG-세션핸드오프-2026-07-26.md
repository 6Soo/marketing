### 날짜 데이터 주의사항

API의 `date + nights`가 대부분 맞지만 아래 원문은 불일치가 확인되어 제목의 날짜를 우선 검토해야 한다.

- 야마구치 추석 여행: 제목 `9/23~24~27`, API 시작일 `9/24`, nights 1
- 서호주 남부: 제목 `9/24~10/5`, API 날짜 `10/04`, nights 11
- 성도·황룡·구채구: 제목은 4박 5일이나 nights 0
- 미야자키 시와쓰마쯔리: 제목 `1/24~29`, API 날짜 `2026-12-18`

잘못된 날짜를 그대로 공개하지 말고 카페 원문 또는 예약 상세 페이지를 확인한 뒤 등록한다.

## 6. OG 문제 진단

9개 여행 상세 URL의 HTML 응답을 직접 확인한 결과 모두 아래 메타데이터를 반환했다.

- `og:title`: `숲길따라 감성여행`
- `og:description`: `지금 모집 중인 여행을 한자리에 모아 보여드려요`
- `og:image`: `https://reserve.foresttour.kr/og.jpg`

따라서 밴드는 서로 다른 여행 링크를 구분하지 못하고 동일한 OG 카드를 반복 표시한다.

### 원하는 최종 동작

- 메인·목록·대표 페이지: 기존 `/og.jpg` 유지
- `/tour/<id>` 상세 페이지:
  - 여행별 `og:title`
  - 여행별 요약 `og:description`
  - 여행별 `og:image`
- 메타데이터는 클라이언트 렌더 후가 아니라 최초 서버 HTML 응답에 포함
- 이미지는 절대 HTTPS URL
- 밴드 캐시가 남으면 배포 후 링크 카드 재생성 또는 `&og=<version>`으로 캐시 갱신

## 7. OG 이미지 선정 정책

카페 글의 첫 사진을 무조건 쓰지 않는다.

### 자동 탈락 기준

- 회사 촬영 또는 홍보 사용 승인이 불명확
- 얼굴이 크게 보이거나 초상권 확인이 어려움
- 1200×630 미만 또는 심한 흔들림·과노출
- 가로 크롭 시 핵심 피사체 소실
- 워터마크, 날짜, 연락처, 차량번호, 채팅 캡처 포함
- 여행 지역·주제와 불일치
- 다른 여행에서 이미 사용한 사진

### 권장 데이터 필드

```text
ogImage
ogImageSource: cafe | pexels | wikimedia | ai | default
ogImageApproved
ogImageLicense
ogImageVersion
```

### 이미지 확보 순서

1. 승인된 카페·대장 촬영 실사진
2. Pexels 실제 사진 검색
3. Wikimedia Commons의 CC0·퍼블릭 도메인
4. Cloudflare Workers AI의 FLUX.1 Schnell 생성
5. 모두 실패하면 기존 공통 `/og.jpg`

페이지 요청 때마다 검색·생성하지 않고 여행 생성·수정 시 한 번만 실행하고 결과를 저장한다.

## 8. 무료 서비스 조사

### Pexels

- 기본 200회/시간, 20,000회/월 무료
- 상업적 웹사이트·마케팅 사용 가능
- API 가이드에 맞춰 Pexels 링크와 가능하면 작가 출처를 상세 페이지에 기록
- 이미 `marketing/tools/stock-photo.mjs`와 `.env`의 `PEXELS_API_KEY` 사용 흔적이 있음
- 가장 현실적인 실제 사진 검색 1순위

### Wikimedia Commons

- 무료지만 이미지별 라이선스와 저작자 표시 조건이 다름
- 자동화에서는 CC0 또는 퍼블릭 도메인만 채택하는 것이 단순하고 안전

### Cloudflare Workers AI

- 무료 플랜 하루 10,000 Neurons
- FLUX.1 Schnell 텍스트-이미지 생성 지원
- 소량의 여행 OG 생성에는 무료 범위가 충분할 가능성이 높음
- 생성 이미지는 실제 명소 사진처럼 단정하지 말고 `AI 생성 이미지` 표시 권장

### Hugging Face

- 무료 사용자의 Inference Providers 크레딧은 월 $0.10 수준
- 시험용으로는 가능하나 안정적인 운영 폴백으로는 부족

## 9. 권장 구현 파이프라인

```text
여행 생성·수정
  → 제목에서 지역·계절·여행 유형 규칙 추출
  → 승인된 실사진 점수화
  → Pexels 검색 및 후보 캐시
  → Commons CC0/PD 검색
  → Cloudflare FLUX 1회 생성
  → 1200×630 OG 가공
  → 저장소에 업로드
  → 여행 레코드에 URL·출처·승인·버전 저장
  → /tour/<id> 서버 메타데이터에서 사용
```

지역명 추출은 표준 지역 사전과 정규식으로 처리해 LLM 토큰을 사용하지 않는다. 같은 `지역+계절+여행유형` 조합은 콘텐츠 해시로 재사용한다.

## 11. 새 marketing 세션이 바로 할 일

1. 이 문서와 `AGENTS.md`, `CLAUDE.md`, `LOG.md`의 최신 블록을 읽는다.
2. 다른 세션의 미커밋 변경을 보존한다.
3. 밴드 추가 일정 등록 결과와 실패·보류 목록을 이 문서에 갱신한다.
4. `reservation` 리포에서 `/tour/<id>` 동적 OG 메타데이터 구현 위치를 찾는다.
5. `marketing/tools/stock-photo.mjs`를 재사용해 Pexels 검색 모듈을 분리한다.
6. 이미지 적격성 검사와 캐시·출처 데이터 구조를 먼저 구현한다.
7. Cloudflare Workers AI는 실제 사진 후보가 없을 때만 호출한다.
8. 대표 `/og.jpg`는 유지한다.

## 12. 운영 원칙

- 밴드 SEO는 검색어를 억지로 반복하지 않고 지역·걷기·자연여행 의도를 자연스럽게 작성한다.
- OG에 AI 생성 이미지를 쓰더라도 실제 현지 사진이라고 오인시키지 않는다.
- 회원 실명·전화번호·계좌번호 등 PII를 저장소나 밴드 본문에 기록하지 않는다.
- 기존 게시글 수정·삭제는 사용자의 명시적 요청 없이는 하지 않는다.
