## 1. 사장님이 하실 일 — 숫자만 채우기

파일 두 개가 이미 만들어져 있습니다. 여기 `"숫자입력"`만 바꾸시면 됩니다.

- 사도: `data/instagram-ui/sado-003-24h.json`
- 북알프스: `data/instagram-ui/northern-alps-004-24h.json`

### 인스타 화면 → 파일 필드 대응표

게시물 하단 **"인사이트 보기"** → 상세 화면의 숫자를 아래 자리에 그대로 옮겨 적습니다.

| 인스타 인사이트 화면 항목 | 파일에서 바꿀 자리 |
| --- | --- |
| **도달한 계정** (Accounts reached) | `insights.data` 중 `"name": "reach"` 의 `total_value.value` |
| **저장** (Saves, 북마크 아이콘) | `"name": "saved"` 의 `total_value.value` |
| **공유** (Shares, 종이비행기 아이콘) | `"name": "shares"` 의 `total_value.value` |
| **좋아요** (하트 아이콘) | `media.like_count` |
| **댓글** (말풍선 아이콘) | `media.comments_count` |

### 입력 규칙 (딱 4개)

1. **따옴표 없이 숫자만.** `"숫자입력"` → `41` (O) / `"41"` (X) / `41명` (X)
2. **모르는 값·화면에 안 보이는 값은 `"숫자입력"` 그대로 둡니다.** 그 항목만 기록에서 빠지고,
   나머지는 정상 저장됩니다. 다섯 개를 다 채울 필요 없습니다.
3. **0이나 null을 임의로 쓰지 마세요.** 화면에 실제로 `0`이라고 적혀 있을 때만 `0`을 씁니다.
4. **`permalink` 줄은 절대 건드리지 마세요.** 이 URL로 게시물을 찾습니다. 한 글자만 달라도
   "게시물을 찾지 못했습니다"로 전체가 거부됩니다.

### 부분 입력 예시 (실측 확인됨)

도달 41, 저장 3, 좋아요 5만 확인되고 공유·댓글은 화면에 없던 경우:

```json
"like_count": 5,
"comments_count": "숫자입력",
...
{ "name": "reach",  "total_value": { "value": 41 } },
{ "name": "saved",  "total_value": { "value": 3 } },
{ "name": "shares", "total_value": { "value": "숫자입력" } }
```

→ 실제 기록: `{"reach":41,"saves":3,"likes":5}` — 공유·댓글은 **없는 것으로** 남습니다. 정상입니다.

## 2. 왜 0/null을 쓰면 안 되는가 — 코드가 어떻게 막는가

**"모른다"와 "0으로 관측했다"는 완전히 다른 사실입니다.** 이 구분이 무너지면 활성화 판정이 통째로
오염됩니다. 그래서 파이프라인 세 지점에서 강제됩니다.

**(1) 추출 단계 — `tools/collect-instagram-activation-metrics.mjs:51`**

```js
if (Number.isInteger(Number(value)) && Number(value) >= 0) metrics[name] = Number(value);
```

`"숫자입력"` → `Number("숫자입력")` = `NaN` → 정수가 아니므로 **필드 자체가 만들어지지 않습니다**.
반대로 `0`은 정수이자 0 이상이므로 **"관측된 0"으로 그대로 저장됩니다.** 이게 0을 쓰면 안 되는
기계적 이유입니다. 0은 빈칸이 아니라 데이터입니다.

**(2) 전량 미입력 방어 — 같은 파일 53행**

```js
if (!Object.keys(metrics).length) throw new Error('게시물에서 확인 가능한 Instagram 지표가 없습니다.');
```

다섯 칸을 전부 플레이스홀더로 두면 **파일이 아예 기록되지 않고 종료 코드 1로 실패합니다.**
빈 껍데기 체크포인트가 "기록됨"으로 위장되는 걸 막습니다. (2026-07-28 실측 확인 — 4장 참조)

**(3) 저장 단계 — `tools/record-instagram-activation.mjs:33-37`**

```js
if (!/^\d+$/.test(value)) throw new Error(`${name}은 0 이상의 정수여야 합니다.`);
```

음수·소수·문자열은 저장 직전에 다시 한 번 거부됩니다.

테스트로도 고정돼 있습니다: `tools/record-instagram-activation.test.mjs` 의
**"확인하지 않은 수치를 0으로 만들지 않는다"**, `collect-instagram-activation-metrics.test.mjs` 의
**"고유 sourceCode의 foresttour 퍼널만 합산하고 관측된 0을 보존한다"**.

### 스냅샷으로는 못 들어가는 지표

`organicInteractions` · `profileVisits` · `follows` · `postsTotal` · `followersTotal` ·
`followingTotal` 은 **스냅샷 파일에서 읽지 않습니다**(추출기가 reach/saved/shares/likes/comments
다섯 개만 매핑). 이 값들은 별도 CLI로 직접 기록합니다.

```
node tools/record-instagram-activation.mjs \
  --experiment=sado-003 --checkpoint=24h --source=instagram-ui \
  --organicInteractions=<확인한 수>
```

중요: `activationStatus`는 `organicInteractions > 0` 이어야 "초기 활성화 증거" 판정을 냅니다
(`record-instagram-activation.mjs:106`). 좋아요 합계로 대신 추정하지 않습니다 — 소유자 본인
좋아요가 섞이기 때문입니다. 확인 안 됐으면 그냥 기록하지 마세요.

## 3. 실행 명령 정본 (로컬)

숫자를 채운 뒤, 리포 루트(`/Users/6soo/orca/marketing`)에서 실행합니다.

**사도 — 인스타 쪽**

```
npm run activation:collect -- \
  --experiment=sado-003 \
  --checkpoint=24h \
  --instagram-source=instagram-ui \
  --instagram-file=data/instagram-ui/sado-003-24h.json
```

**북알프스 — 인스타 쪽**

```
npm run activation:collect -- \
  --experiment=northern-alps-004 \
  --checkpoint=24h \
  --instagram-source=instagram-ui \
  --instagram-file=data/instagram-ui/northern-alps-004-24h.json
```

`--instagram-source=instagram-ui` 를 빼면 기본값이 `graph-api`라 **출처가 거짓으로 기록됩니다.
반드시 붙입니다.**

**foresttour 쪽 (같은 24h를 완전하게 만들려면 필수)**

```
FORESTTOUR_ADMIN_KEY=<키> npm run activation:collect -- \
  --experiment=sado-003 --checkpoint=24h --foresttour-live
```

키가 없으면 `/admin/traffic` 집계 JSON을 받아 파일로 저장한 뒤 `--foresttour-file=<경로>`를 씁니다.
`--foresttour-live`와 `--foresttour-file`은 함께 쓸 수 없습니다.
(키 값은 이 리포에 적지 않습니다.)

**확인**

```
npm run activation:status -- --experiment=sado-003
npm run activation:status -- --experiment=northern-alps-004
```

`| 24h | ... | recorded |` 로 바뀌고 `Missing source groups`가 `—`가 되면 완료입니다.
종료 코드 2는 "아직 due인 체크포인트가 있다"는 뜻이지 실패가 아닙니다.

## 4. GitHub Actions로 돌릴 때 (`instagram_snapshot_path`)

워크플로: `.github/workflows/instagram-activation-checkpoints.yml`

**dispatch 입력값 (실험마다 1회씩, 총 2회 실행)**

| 입력 | 사도 | 북알프스 |
| --- | --- | --- |
| `experiment` | `sado-003` | `northern-alps-004` |
| `instagram_snapshot_path` | `data/instagram-ui/sado-003-24h.json` | `data/instagram-ui/northern-alps-004-24h.json` |

경로는 **리포 루트 기준 상대 경로**이고, 워크플로가 `test -f`로 존재를 먼저 확인합니다.
숫자를 채운 스냅샷 파일이 **브랜치에 커밋·푸시된 뒤**에 실행해야 합니다(체크아웃된 트리에서
읽기 때문). `experiment`를 비우면 게시된 모든 실험이 매트릭스로 돌면서 **같은 스냅샷 경로를
전 실험에 적용**하므로, 반드시 실험을 하나씩 지정합니다.

**실행 순서**

1. `discover` — `npm run test:instagram` 통과 후 대상 실험 목록 산출
2. `Determine due checkpoint` — `collect-now`인 체크포인트를 계산(현재 두 실험 모두 `24h`)
3. `Use supplied Instagram UI snapshot` — `instagram_snapshot_path`가 있으면 파일 존재 확인
4. `Record Instagram activation metrics` — `--instagram-source=instagram-ui`를 자동으로 붙여 수집
5. `Record foresttour activation metrics` — `ACTIVATION_COLLECT_ENABLED=true` + `FORESTTOUR_ADMIN_KEY`
   가 있을 때만 실행. **없으면 이 단계는 건너뛰므로 24h는 여전히 불완전으로 남습니다.**
6. `Require at least one collected source` — `data/activation/<실험>`에 diff가 없으면 실패 처리
7. `Persist collected checkpoint` — 봇 계정으로 커밋·리베이스·푸시
8. `Report due checkpoints` / `learn` — 요약 출력

`instagram_snapshot_path`를 주면 `ACTIVATION_COLLECT_ENABLED`가 `true`가 아니어도 인스타 쪽은
수집됩니다(“Refuse silent checkpoint miss” 단계를 우회). 다만 foresttour 쪽은 여전히 안 돌아갑니다.
