# 숲길따라 감성여행 네이버 밴드 운영 인계 1차 실행안

- 작성일: 2026-07-28
- 기반: 2026-07-28 설계·적대적 반박·재반론 검증 사이클의 확정안
- 범위: 첫 2주 편성표 · 즉시 게시 가능한 글 초안 5편 · 사진 소싱 규칙 · 달력 점유 UI 악화 중단 및 단계적 접근안 · 기존 일정 수정 안전 조건 · 신규 대표일 파일럿 조건 · 롤백 절차 · 측정과 판정 · 권한 부족 처리 · 운영 로그 양식 · 체크리스트 및 미확정 목록
- 외부 BAND 게시·수정·삭제: **본 문서 작성 단계에서는 전부 금지** (메인 세션의 브라우저 실측 및 실행 직전 확인 뒤 수행)
- 개인정보 보호: 계정명, 실명, 연락처, 계좌번호, 참석자명, 댓글 원문을 저장소에 기록하지 않음

## 1. 개요 및 최종 판정

기존 네이버 밴드 피드가 **일정 공유글로 도배되는 문제**를 해결하고, **여행지 발견 → 욕구 → 낮은 압력의 일정 연결** 구조로 전환하기 위한 1차 실행을 확정한다.

### 1.1 핵심 실행 원칙 (시니어 원칙: 관찰 → 한 가지 작은 변화 → 반응 검증 → 확대)
1. **기존 8월 일정 9건 보존**: 1차 실행에서 기존 일정을 수정하거나 삭제하지 않는다.
2. **미등록 개별 일정 52건 동결**: 인계서 상의 52건 신규 개별 일정 등록을 계속 동결한다.
3. **첫 2주 텍스트 초안 5편 게시**: 사진·외부 링크 없이도 성립하는 짧은 일상글 5편을 `T0` 상대 일정으로 순차 게시한다.
4. **일정 연결 압력 최소화**: 직접 URL 딥링크를 본문/댓글에 넣지 않고, BAND 내 기존 `일정` 탭 안내 수준으로 제한한다.
5. **대안 D 채택 (월 1회 출발 색인 공지 - 악화 중단안)**: 첫 2주 5편 게시 및 기준선 확인 후, 필요 시 1건만 게시한다.
6. **신규 대표일 파일럿 (대안 A)**: 2주 후 회원의 일정 탐색 수요 확인 시 신규 미래 일정 1건으로만 파일럿 검증한다.
7. **딥링크 완전 제거**: OG 메타데이터 및 착륙 화면 검증(G3 게이트) 통과 전까지 본문·댓글·일정 설명의 직접 링크를 차단한다.

## 2. 밴드 문법 및 사례 참고 (레포 원칙 반영)

### 2.1 타 밴드 사례의 위치 (final R7 반영)
- 마운틴TV의 멤버 산행기, 아웃도어스쿨의 단일 행사 안내, BAND 공식 취미 모임 사례는 가능한 문법을 보여주는 **참고 사례일 뿐 인과/효과의 근거가 아니다.**
- 공개 웹에서 규모와 최근 피드 구성을 검증하지 못한 사례는 편성 비율의 근거로 쓰지 않으며, 우리 밴드의 자동 실행 규칙으로 이식하지 않는다.

### 2.2 레포 운영 원칙 (`CLAUDE.md`, `strategy/밴드-활성화-전략-0721.md`)
- 밴드는 5060·모임 문화·소박함이 핵심 문법이다. (2030 중심 인스타그램의 풀블리드 visual 카드뉴스와 구분)
- 현지에 있다는 허위 1인칭 표현을 금지한다.
- PII(개인식별정보: 계정, 전화번호, 계좌, 참석자명)를 저장소 및 밴드 본문에 노출하지 않는다.

## 3. 첫 2주 편성표 (`T0` 상대 편성)

실행 기준일 `T0`는 메인 세션이 기준선 수집과 게시 본문 확인을 마친 다음 날을 의미한다.

### 3.1 T0 이전 — 읽기 전용 준비 (5항목 전체)
1. 메인 세션 브라우저에서 현재 BAND의 멤버 수와 시각을 기록한다.
2. 최근 게시글 20건을 `여행지/후기`, `일정`, `판매`, `운영공지`로 분류하고 각 댓글·반응 숫자만 기록한다.
3. 기존 9건의 공개 ID, 제목, 시작일, 종료일, 댓글 수, 참석 응답 수, 공유 여부를 확인한다.
4. 계정 역할과 수정 버튼 유무를 확인하되 **저장은 누르지 않는다.**
5. 초안 5편에서 날짜, 링크, 사진 전제, PII가 없음을 다시 확인한다.

### 3.2 T0~T0+13 relative 편성표

| 상대일 | 역할 | 주제 | 외부 링크 | 사진 전제 | 비고 |
|---|---|---|---|---|---|
| **T0** | 발견 | 여름에 떠오르는 조용한 길 | 없음 | 선택 | 하루 최대 게시 1편 |
| **T0+3** | 욕구 | 천천히 걷는 날 | 없음 | 선택 | 최소 48시간 간격 준수 |
| **T0+6** | 낮은 압력 연결 | 일정은 필요할 때 | 없음 | 없음 | 텍스트 전용 |
| **T0+9** | 관계 | 오래 남는 장면 | 없음 | 선택 | 관계형 댓글 유도 |
| **T0+13** | 참여 | 다음에 읽고 싶은 길 | 없음 | 없음 | 텍스트 전용 |
| **T0+14** | 판정 | 기준선 vs 5편 사후 비교 | 없음 | 없음 | D 유지 / A 파일럿 / C 유지 결정 |

### 3.3 편성 기간 필수 제약
- 일정 수정·삭제·신규 일정 생성은 이 기간에 하지 않는다.
- 월간 색인 공지는 5편과 같은 날 게시하지 않는다.
- 글 사이 최소 48시간을 둔다. (게시 시점이 밀리면 이후 글을 같은 간격으로 이동하며 본문은 바꾸지 않는다.)

## 4. 즉시 게시 가능한 글 초안 5편

모든 초안은 **텍스트만으로 완전히 성립**한다. 사진이 없어도 그대로 게시 가능하며, 날짜·가격·상품 링크·대장명·연락처·계좌번호·PII가 전혀 없다. (마크다운 백틱 표기 없음)

### 초안 1 — 여름의 조용한 길 (T0 게시)
```text
한여름이 되면
시원한 곳보다 조용한 길이 먼저 생각납니다.

나무 사이로 햇빛이 조금씩 들어오고,
마음에 드는 자리가 있으면 잠깐 멈추는 길이요.

빠르게 많이 보는 날보다
한 곳을 천천히 걷는 날이 오래 남을 때가 있습니다.

오늘은 여러분께도
그런 길 하나를 조용히 건네고 싶었습니다.
```

### 초안 2 — 천천히 걷는 날 (T0+3 게시)
```text
걷다 보면 유난히 발걸음이 느려지는 날이 있습니다.

힘들어서가 아니라
그늘도 보고 바람도 느끼고 싶어서요.

여행은 늘 멀리 가야 기억에 남는 것은 아닌 것 같습니다.

조금 천천히 걸었던 시간이
나중에는 더 선명하게 떠오르기도 하니까요.

여러분은 산길과 물길 중
어느 쪽에서 더 천천히 걷게 되시나요?
```

### 초안 3 — 일정은 필요할 때 (T0+6 게시)
```text
여행 이야기를 읽다가
날짜가 궁금해지는 순간이 있습니다.

그럴 때는 밴드의 일정 탭에서
마음이 가는 여행 이름을 눌러보시면 됩니다.

한꺼번에 다 살펴보지 않으셔도 괜찮습니다.

먼저 가보고 싶은 곳을 만나고,
날짜는 그다음에 천천히 확인해보세요.
```

### 초안 4 — 오래 남는 장면 (T0+9 게시)
```text
여행이 끝난 뒤에는
유명한 장소보다 작은 장면이 더 오래 남기도 합니다.

아침에 마신 따뜻한 차,
걷다가 함께 쉬었던 나무 그늘,
숙소로 돌아오며 본 저녁빛 같은 것들이요.

여러분의 지난 여행에서
지금도 문득 떠오르는 장면이 있으신가요?

짧게 한 가지씩 나눠주셔도 좋겠습니다.
```

### 초안 5 — 다음에 읽고 싶은 길 (T0+13 게시)
```text
다음에는 어떤 길 이야기를 읽고 싶으신가요?

나무 냄새가 좋은 숲길,
걷고 나서 쉬어가는 온천마을,
바람 소리가 가까운 섬길.

정답은 없습니다.

마음이 가는 것 하나만 남겨주시면
앞으로의 글감을 고를 때 참고하겠습니다.
```

### 4.1 사진 사용 및 저작권 수칙 (final R4 전문 반영)
사진은 선택 사항이며, 없으면 본문을 바꾸지 않고 그대로 게시한다. 사진을 추가할 경우에만 아래 3순위를 따른다.

1. **소싱 1순위**: 화면 기준을 통과한 Commons PD · CC0 · CC BY 제3자 촬영본
2. **소싱 2순위**: 화면 기준과 사용 권한을 통과한 대장 원본
3. **소싱 3순위**: 없으면 사진 없이 게시

- **CC BY 크레딧 필수 표기**: CC BY 이미지를 사용할 경우 게시글 말미에 아래 형식으로 반드시 적는다.
  `사진: 저작자 / CC BY 버전 / 원문 URL`
- **금지 조항**: CC BY-SA, AI 생성 이미지, Pexels 이미지는 1차에 사용하지 않는다.
- **초상권 및 PII 금지**: 얼굴 식별이 가능한 사진과 PII(개인식별정보)가 포함된 이미지는 사용하지 않는다.

## 5. 달력 점유 UI 악화 중단 및 단계적 접근안

### 5.1 문제 현상 (메인 세션 실측 전 미확정)
- 여러 날짜(예: 3박 4일, 10박 11일) 여행이 네이버 밴드 달력에 각각 등록될 때, 달력 UI 상 일정 바(Bar)가 어떻게 표시되는지 및 탐색 비용에 미치는 영향은 **메인 세션 실측 전까지 미확정**이다.
- 다만, 기존 피드가 일정 공유글로 도배되는 현상을 막기 위해 추가 작성을 중단한다.

### 5.2 대안 D 채택 (기존 보존 + 신규 동결 + 월 1회 출발 색인 공지)
- **기존 9건 일정**: 1차 실행 시 수정·삭제하지 않는다. (과거 진행/종료 일정도 과거 기록으로 보존하며 달력 정리를 이유로 삭제하지 않는다.)
- **신규 개별 일정**: 인계서 52건 일괄 등록을 **전면 동결**한다.
- **월 1회 출발 색인 공지 규칙 (final §5 전문)**:
  - 첫 2주 후 필요성이 확인될 때 상단 고정 공지로 `YYYY년 M월 출발일 한눈에 보기` 1건 작성 (외부 게시 전 메인 세션 확인 필수).
  - **제목**: `YYYY년 M월 출발일 한눈에 보기`
  - **범위**: 게시일 다음 날부터 30일 안에 출발하는 여행, 최대 5건 (5건을 넘으면 가까운 출발일 5건만 싣고 나머지는 일정 탭에서 확인).
  - **항목**: `M/D · 여행지명 · N박N일`
  - **날짜 출처**: 카페 원문과 reserve 상세가 일치한 건만 입력.
  - **제외 항목**: 가격, 잔여석, 대장명, 링크, 연락처, 계좌, 예약 압박.
  - **말미 문구**: `마음이 가는 여행의 자세한 내용은 밴드 일정에서 이름을 눌러 확인해주세요.`
  - **고정 규칙**: 월간 공지 1건만 고정 유지. 다음 달 공지가 올라오면 이전 공지의 고정을 해제.
  - **수정 규칙**: 날짜가 바뀌면 원출처 재확인 뒤 제자리 수정하고 변경 사실 한 줄 표기.

### 5.3 신규 대표일 일정 파일럿 (대안 A - final §6.2/R6 조건 전문)
첫 2주 후 회원의 일정 탐색 필요가 확인되고 아래 조건이 모두 통과될 때만 **새 일정 1건**으로 파일럿한다. UI 동작(하루 종일 바 표시, 알림/공유)은 **메인 세션 실측 전 미확정** 상태이다.
- **출발 기한**: 출발까지 최소 21일 이상 남아있음. (국제선 일정 연결 21일 하한 규칙 적용)
- **날짜 일치**: 카페 원문 제목·본문 날짜와 reserve 상세 날짜가 완전 일치함.
- **기존 일정 부재**: 기존 BAND 일정이 없음.
- **UI 설정 사전 확인**: 게시글 공유 끄기와 알림 동작을 저장 전 화면에서 확인함.
- **권한 확인**: 로그인 계정이 리더 또는 권한 있는 공동리더임.
- **검증 가능성**: 변경 전후 공개 화면을 PII 없이 검증 가능함.
- **양식**: 달력 표시는 출발일 하루 종일, 제목 `[출발] M/D 여행지 · N박N일`, 설명 첫 줄 `전체 여행기간: YYYY.M.D–M.D`, 참석 조사 끔.
- **조건 미충족 시**: 조건을 만족하는 건이 없으면 파일럿을 하지 않는다.
- **확대 금지**: 한 파일럿의 성공을 52건 전체에 일반화하지 않고, 두 번째 건 재현 전까지 확대를 금지한다.

### 5.4 기존 일정 수정의 조건부 안전안 (final §6.3 전문)
기존 9건 수정은 1차 범위 밖이다. 이후에도 아래 7개 선행 조건을 모두 만족할 때만 1건을 후보로 삼는다.
1. 출발 전이며 출발까지 21일 이상 남음
2. 댓글·참석 응답이 0건임
3. 카페 원문과 reserve 상세 날짜가 일치함
4. 현재 역할에 수정 권한이 있음
5. 저장 시 재공유·알림 동작이 확인됨
6. 변경 전 구조화 로그 작성 완료
7. 메인 세션 실행 직전 확인 완료

- **수정 후 사후 검증**: URL, 기간, 댓글 수, 응답 수, 달력 표시, 새 피드 공유글 생성 유무를 확인.
- **1회 원값 복원**: 위 항목 중 하나라도 달라지면 원래 종료일로 한 번만 복원하고 나머지는 조작을 중단한다.
- **위험 여행 수정 금지**: 가장 긴 여행을 위험 재현 목적으로 먼저 수정하지 않는다.

## 6. 로그인 계정별 권한 부족 처리 절차

| 상태 | 대응 행동 | 금지 사항 |
|---|---|---|
| **리더 / 권한 있는 공동리더** | 허가된 1건만 안전 실행 | 일괄 수정 / 무단 삭제 |
| **멤버 / 작성자 아님** | 읽기 전용으로 관측 후 `permission_denied` 로그 남김 | 우회 수정 시도 |
| **수정 버튼 없음** | 조작 중단 및 사용자에게 역할 전환 요청 | 계정명/이메일 저장소 기록 |
| **로그인 만료/2차인증/CAPTCHA** | 사용자에게 브라우저 로그인 재개 요청 | 자동 로그인 재시도, 보안 우회 |
| **역할 불명** | 읽기 전용으로 세션 종료 | 권한 추정 후 실행 |

### 권한 부족 시 사용자 안내문 템플릿
```text
현재 로그인 역할에서는 필요한 수정 권한을 확인할 수 없어 외부 변경을 중단했습니다.
일정 수정 권한이 있는 리더 또는 공동리더 역할로 로그인한 뒤 다시 확인해 주세요.
계정 정보와 인증값은 저장소에 남기지 않습니다.
```

## 7. 게이트 및 회귀 안전 조건

### 7.1 실행 게이트
- **G1 (콘텐츠)**: 초안 텍스트전용 성립, PII/날짜/가격/링크/대장명 미포함, 1인칭 허위 표현 없음, 사진 첨부 시 권리·장소·크레딧 표기 확인.

- **G4 (외부 실행)**: 메인 세션의 브라우저 실측 및 확인 후 실행. 하루 최대 게시 1편.

- **기존 일정 수정·삭제 수**: 0건

## 8. 측정과 판정 (final §3 T0+14 및 §10 수용분)

### 8.1 T0+14 판정 질문 (4가지)
1. 일정 탭을 찾기 어렵다는 반응이 반복되는가?
2. 여행지 글에 기존 일정 공유글보다 관계형 댓글이 붙는가?
3. 월간 색인이 운영 부담을 줄이는가?
4. 대표일 파일럿이 실제로 필요한가?

### 8.2 사후 관찰값
- 5편 발행 완료 수
- 글별 댓글 및 반응 숫자
- 일정 탐색 질문 유형 수
- 최근 20건 기준선 대비 새 글의 반응 방향
- 월간 색인 작성·검증에 든 운영 시간

*주의: 표본이 작으므로 통계적 "성공률"을 주장하지 않는다. 다음 행동은 `D 유지`, `A 파일럿 1건`, `C 유지` 중 하나를 메인 세션이 명시적으로 확정한다.*

## 9. 롤백 절차 (final R13 수용분)

1차에는 일정을 수정하지 않아 일정 롤백이 발생하지 않는다. 향후 파일럿 또는 조건부 수정 시 아래 절차를 적용한다.

- **보존 필드 7종**: 일정 공개 ID, 제목, 시작일, 종료일, 하루 종일 여부, 공유 여부, 알림 경고 상태.
- **1회 원값 복원**: 검증 실패(URL·제목·기간·댓글 수·응답 수 변경) 시 같은 세션에서 원값으로 한 번만 복원.
- **복원 검증 실패 시**: 추가 조작 중단, `rollback_failed` 기록, 메인 세션 보고.
- **금지 수단**: 삭제 및 재생성을 롤백 수단으로 사용하는 것을 금지한다.

## 10. 외부 실행자의 최종 체크리스트 (final §11 전문)

1. 기존 9건과 미등록 52건에 쓰기 작업을 하지 않는다.
2. 최근 20건 기준선을 PII 없이 기록한다.
3. 초안 1편만 복사하고 게시 전 링크·날짜·사진 전제 없음 확인.
4. 실제 게시 화면에서 본문이 잘리지 않는지 확인한 뒤 게시.
5. T0+3, +6, +9, +13 순서로 반복.
6. 2주 뒤 기준선과 비교하고 D/A/C 중 다음 상태를 명시.
7. 월간 색인 또는 대표일 파일럿은 별도 실행 직전 확인 없이는 만들지 않는다.
8. 외부 게시·수정·삭제 결과를 이 문서에 사후 추정으로 적지 않고 운영 로그에 확인값만 남긴다.

## 11. 메인 세션 실측 전 미확정 목록 및 최종 기본값 (final §12 전문)

### 메인 세션 실측 전 미확정 항목
- 현재 멤버 수와 기존 카페 회원 비중
- 현재 로그인 역할의 실제 수정 권한
- 일정 저장 시 알림·재공유 동작
- 기존 공유글과 일정의 삭제 결합 관계
- 대표일 일정이 기존 회원의 탐색 비용을 실제로 낮추는지
- 여행별 OG와 착륙 화면 개선 배포 여부

### 최종 기본값
미확정 항목은 추정으로 채우지 않는다. 미확정이 외부 변경의 안전성에 영향을 주면 **쓰기 작업을 하지 않는 것이 최종 기본값**이다.
