# 숲길따라 감성여행 네이버 밴드 운영 인계 — 2차 정정 실행안

- 최초 작성: 2026-07-28
- 2차 정정: 2026-07-28
- 대상: 네이버 BAND `56995933`
- 외부 쓰기: 이 문서 정정 단계에서는 게시·수정·삭제하지 않음
- 개인정보: 계정명·실명·연락처·계좌번호·참석자명·댓글 원문을 저장소에 기록하지 않음

## 0. 2차 정정 — 현재 일정 수는 UI 감사 전 미확정

과거 marketing 핸드오프의 숫자는 당시 작업 목록이었다.

- `61`: 2026-07-26 당시 예약 API에서 계산한 2026년 8월 이후 여행 후보 수 (최초 9건 배치 + 후속 후보 52건)
- `9`: 최초로 등록한 2026년 8월 일정 배치
- `52`: 당시 계산한 후속 등록 후보 수

foresttour 최신 인계 기록은 2027-01-16 출발분까지 등록을 완료로 확인했고, 2027-01-24 이후 11건의 추가 등록과 월별 달력 검증을 미완료로 기록했다. 이후 2026-07-29 BAND UI에서 2026-08~2027-04를 월별로 다시 감사해 **해당 11건이 모두 달력에 존재함을 확인했다.** 이 11건은 다시 생성하지 않는다. 전체 고유 일정 수, 중복 수, 공유글 연결 수는 별도 ID 감사 대상이다.

또한 foresttour 저장소의 기존 BAND 실행안(다일 일정 + 게시글 동시 생성 + 상세 링크 분리)과 본 실행안(출발일 하루 + 공유 끄기)의 정책 충돌에 따라 foresttour 문서는 `superseded_pending_sync` 상태로 취급하며, 두 문서가 정렬될 때까지 쓰기의 단일 실행 주체는 메인 세션 하나로 제한한다 (실행 잠금).

## 1. 최종 목표

### 1.1 신규 일정 기본 규칙

- 여행 하나당 일정 하나
- 달력 표시: **출발일 하루 종일 1일**
- 제목: `[출발] M/D 여행지 · N박N일`
- 본문 첫 줄: `전체 여행기간: YYYY.M.D–M.D`
- 날짜: 카페 원문과 reserve 상세가 일치한 경우만
- `게시글로 공유`: 끔
- 참석 조사: 실제 예약과 혼동하면 끔
- 저장 뒤 피드 신규 일정 공유글 0건 확인

### 1.2 기존 일정 정정 목표 및 실행 상한

2026-07-29 월별 감사 결과, 미래 일정 누락보다 피드의 일정 자동 공유글 과다와 대화 부재가 더 직접적인 활성화 병목이었다. 다일 일정은 달력을 과밀하게 하지만 여행기간 정보도 제공하므로 출발일 하루 일정으로 일괄 축소하지 않는다. 먼저 신규 일정의 `게시글로 공유` 기본값을 끄는 파일럿과, 상품 링크 없는 참여형 질문·현장 사진 글로 대화 신호를 회복한다. 기존 일정 수정은 댓글·참석·공유글 결합 관계가 확인된 건만 별도 소배치한다.

실행 상한 및 제약:
- 성공 변경 저장: 하루 최대 3건, 1일 1세션, 주 최대 2일
- 실패 시 원복 저장: 해당 실패 건 1회만 허용
- 예상하지 못한 알림·신규 공유글·피드 재상단 노출 허용 상한: 누적 0건
- 보류 대상: 출발했거나 진행 중인 일정(`active`), 종료된 일정(`past`), 날짜 충돌(`date_conflict`), 중복 의심, 권한 부족, 출발 7일 미만 일정
- engaged 일정 (`multi_day_future_engaged` - 댓글이나 참석 응답이 있는 일정): 회원 전용 안내문 및 영향 검토 전까지 이번 사이클에서 영구 보류

### 1.3 피드 목표

- 새 일정 공유글 자동 생성: 0건
- 여행지·후기·관계형 글: 5편
- 월간 출발 색인: 첫 2주 뒤 필요할 때 별도 1편
- 2주 총 콘텐츠: 5편

콘텐츠 5편은 일정 공유글을 아래로 밀어 문제를 숨기는 수단이 아니다. 신규 일정의 공유를 먼저
끈 뒤 피드의 정상 편집 리듬을 회복하는 후속 단계다.

## 2. 대안과 판정

### 대안 A — 기존 미래 다일 일정 중 적격 건을 대표 출발일 하루로 전환

읽기 감사 후 1건 파일럿, 최대 3건 소배치로 적격 기존 미래 일정을 전환한다.
`multi_day_future_engaged`(댓글·참석 있음), `active`, `past`, `date_conflict`,
중복 의심, 출발 7일 미만 건은 적격 집합에서 제외되므로 "전체 전환"이 아니다.

- 장점: 달력의 다일 점유를 가장 빠르게 줄이고 표시 규칙을 통일한다.
- 트레이드오프: 공개 수정 횟수가 많고 일정별 상태가 달라 감사·검증 비용이 크다.
- 실패 모드:
  - 예상하지 못한 멤버 알림
  - 새 공유글 또는 피드 재상단 노출
  - 일정 URL 변경
  - 댓글·참석 응답 소실
  - 전체 여행기간 유실 또는 날짜 오기
  - 롤백 실패

### 대안 B — 기존 보존, 신규부터 하루 일정 + 월간 색인, 필요 시 단계적 기존 변환

기존 일정은 보존하고 앞으로 만드는 일정만 새 기본 규칙을 적용한다.

- 장점: 기존 URL·댓글·참석·알림 회귀 위험이 가장 낮다.
- 트레이드오프: 이미 등록된 다일 일정의 달력 점유가 남아 체감 해결이 느리다.
- 실패 모드:
  - 기존·신규 표시 방식 혼재
  - 월간 색인이 장문 상품 목록으로 변질
  - 기존 공유글 도배가 출발일까지 지속

### 대안 C — 달력 보존, 공유글만 독립 정리

일정과 공유글이 별도 객체임이 UI에서 입증되면 공유글만 숨김·공유 해제한다.

- 장점: 피드 도배를 직접 줄이고 일정 데이터를 건드리지 않을 수 있다.
- 트레이드오프: 달력의 다일 점유는 해결하지 못한다.
- 실패 모드:
  - 공유글 삭제가 일정 또는 댓글까지 삭제
  - 공유글 URL 단절
  - 삭제 후 복구 불가

### 채택

사용자의 즉시 해결 요구에 맞춰 **대안 A를 목표안으로 채택**한다. 다만 일괄 저장하지 않고
`읽기 감사 → 파일럿 1건 → 최대 3건 배치 → 배치별 검증`으로 실행한다.

파일럿 실패, 권한 부족, 알림·공유 동작 불명, 브라우저 장애에서는 자동으로 대안 B로 전환한다.
대안 C는 일정과 공유글의 독립성이 입증된 경우에만 조합한다.

## 3. 브라우저 복구 후 실행 순서

### 3.1 읽기 감사

로그인된 관리자 탭 하나에서 저장하지 않고 2026년 8월부터 2027년 5월까지 월별로 확인한다.

일정마다 다음을 PII 없이 기록한다.

- 일정 공개 ID/URL
- 제목
- 시작일·종료일·하루 종일 여부
- 본문 전체 여행기간 문구 유무
- 댓글 수·참석 응답 수
- 현재 역할의 수정 버튼 유무
- 게시글 공유 여부
- 연결 공유글 공개 ID/URL(보이는 경우)
- 알림 관련 표시·저장 전 경고 확인 가능 여부
- 카페 원문·reserve 상세 날짜 일치 여부

월 경계를 넘는 같은 일정은 ID 기준으로 한 번만 센다. 각 월의 보이는 일정 수와 전체 고유 ID
수를 따로 기록하고, 고유 ID 감사가 끝나기 전에는 변환하지 않는다.

### 3.2 분류

| 분류 | 정의 | 조치 |
|---|---|---|
| `single_day` | 시작일=종료일 | 유지 |
| `multi_day_future_zero` | 미래 다일, 댓글 0, 참석 0 | 파일럿·1차 배치 |
| `multi_day_future_engaged` | 미래 다일, 댓글 또는 참석 있음 | 고위험 후속 |
| `active` | 현재 여행기간 안 | 수정 금지 |
| `past` | 종료일 경과 | 기록 보존 |
| `date_conflict` | 카페 원문과 reserve 불일치 | 수정 금지 |
| `duplicate_suspected` | 같은 여행·출발일 중복 의심 | 별도 확인 |
| `permission_blocked` | 수정 권한 없음 | 읽기만 |

### 3.3 파일럿

다음을 모두 만족하는 한 건을 고른다.

1. 시작일이 가장 먼 미래
2. 다일 일정이며 아직 출발하지 않음
3. 댓글 0
4. 참석 응답 0
5. 날짜 원출처 일치
6. 현재 역할로 수정 가능
7. 중복 의심 아님

동률이면 여행기간이 더 긴 것을 선택한다. 없으면 파일럿을 만들지 않고 대안 B로 전환한다.

변경 전에는 제목, 시작·종료일, 하루 종일, 본문 기간 문구, 댓글·참석 수, 일정 ID/URL,
공유글 ID/URL, 공유 여부, 알림 경고를 운영 로그에 기록한다.

변경:

- 종료일=시작일
- 하루 종일 유지
- 제목에 `· N박N일` 보완
- 본문 첫 줄에 정확한 전체 여행기간 추가
- 기존 링크와 나머지 본문 보존
- 기존 `게시글로 공유`는 독립적으로 끌 수 있고 영향이 확인된 경우에만 끔

### 3.4 파일럿 검증

- 달력에서 출발일 하루만 점유
- 본문 전체 여행기간 정확
- 일정 URL/ID 유지
- 댓글 수·참석 응답 수 유지
- 기존 공유글 URL/ID 유지
- 새 일정 공유글 0건
- 피드 재상단 노출 없음
- 예상하지 못한 멤버 알림 없음

예상하지 못한 알림은 회수할 수 없는 실패다. 즉시 추가 변환을 중단한다.

### 3.5 점진 변환

1. 파일럿 통과 후 `multi_day_future_zero` 중 출발까지 7일 이상 남은 일정을 시작일 오름차순(가까운 미래 순)으로 소배치 처리한다.
   - 1단계: 향후 60일 구간
   - 2단계: 이후 남은 미래 구간
2. 상한: 하루 최대 3건, 하루 1세션, 주 최대 2일.
3. 각 건 저장 직전 댓글·참석·상태·날짜·권한 재검증.
4. 배치마다 파일럿과 동일한 보존·무알림·무재공유 검증 반복.
5. 한 건이라도 실패 시 해당 건 1회 원복 시도 후 당일 및 후속 배치 즉시 취소·중단.
6. `multi_day_future_engaged`(댓글/참석 응답 있는 일정)는 회원 전용 안내와 영향 검토가 포함된 별도 설계 승인 전까지 이번 사이클에서 영구 보류하며 변환하지 않는다.

완료 기준은 과거 추정 수가 아니라 UI 감사의 `eligible_total` 전부가 변환되고, `held_total`에는 건별 보류 사유가 기록된 상태다.

## 4. 공유글 정정

### 4.1 신규

새 일정은 항상 `게시글로 공유`를 끄고, 저장 뒤 신규 공유글 0건을 확인한다.

### 4.2 기존

| 확인 결과 | 조치 |
|---|---|
| 일정 수정으로 공유글이 갱신되고 재공유 없음 | 유지 |
| 공유글을 일정과 독립적으로 숨김·공유 해제 가능 | 댓글 0건 1개 파일럿 뒤 소배치 |
| 공유글 정리가 일정·댓글에 영향 | 정리 금지 |
| 결합 관계 불명 | 보존 |

삭제는 기본 수단이 아니다. 독립 숨김·공유 해제가 없으면 새 공유글 생성만 중단하고,
콘텐츠 5편으로 피드 편집 리듬을 회복한다.

## 5. 피드 콘텐츠 5편

### 5.1 구성과 편성

일정 파일럿 성공 또는 대안 B 결정 다음 날을 `T0`로 한다.

| 상대일 | 역할 | 내용 |
|---|---|---|
| T0 | 발견 | 여름의 조용한 길 |
| T0+3 | 욕구 | 천천히 걷는 날 |
| T0+6 | 낮은 압력 연결 | 일정은 필요할 때 |
| T0+9 | 관계 | 오래 남는 장면 |
| T0+13 | 참여 | 다음에 읽고 싶은 길 |

- 일정 변환 배치와 콘텐츠 게시를 같은 날 하지 않는다.
- **우선순위**: 5편 편성일을 먼저 고정한다. 콘텐츠 게시 예정일과 일정 변환일이 겹치면
  콘텐츠가 아니라 **일정 변환을 다음 허용일로 옮긴다.** 콘텐츠 성과 판정과 이벤트 정정
  성과 판정은 별도 로그·별도 지표로 유지한다.
- 게시글 하나를 여러 일정에 자동 공유하지 않는다.
- 사진·링크 없이도 성립하는 짧은 존댓말 문장으로 쓴다.
- 현지에 있는 척하는 1인칭, 가격·잔여석·대장명·연락처·계좌를 쓰지 않는다.
- 글 사이 최소 48시간을 두며 일정이 밀리면 이후 글도 같은 간격으로 옮긴다.

### 5.2 월간 출발 색인

- 다음 30일 출발, 최대 5건
- 형식: `M/D · 여행지명 · N박N일`
- 카페 원문과 reserve 상세 날짜 일치 건만
- 가격·잔여석·대장명·연락처·계좌·딥링크 없음
- 말미: `전체 여행기간은 각 BAND 일정 본문에서 확인해주세요.`
- 월간 공지 1건만 고정하고 다음 달 색인 시 이전 고정 해제

월간 색인은 첫 2주 5편과 별개다. 첫 2주 뒤 실제 일정 탐색 질문이 반복될 때만 만들며,
5편과 같은 날 게시하지 않는다.

### 5.3 콘텐츠 측정과 판정 (보존 계약 항목 — 삭제 금지)

이 절은 이전 사이클에서 검증을 통과한 내용이다. 이벤트 정정의 완료율에는 산입하지 않으며,
콘텐츠 5편의 성과만 별도 지표로 판정한다.

#### T0+14 판정 질문 (4가지)

1. 일정 탭을 찾기 어렵다는 반응이 반복되는가?
2. 여행지 글에 기존 일정 공유글보다 관계형 댓글이 붙는가?
3. 월간 색인이 운영 부담을 줄이는가?
4. 대표일 파일럿이 실제로 필요한가?

#### 사후 관찰값

- 5편 발행 완료 수
- 글별 댓글 및 반응 숫자
- 일정 탐색 질문 유형 수
- 최근 20건 기준선 대비 새 글의 반응 방향
- 월간 색인 작성·검증에 든 운영 시간

*주의: 표본이 작으므로 통계적 "성공률"을 주장하지 않는다. 다음 행동은 `A 계속`,
`B 폴백`, `C 보류` 중 하나를 메인 세션이 명시적으로 확정한다.*

### 5.4 즉시 게시 가능한 글 초안 5편

모든 초안은 텍스트만으로 완전히 성립한다. 사진이 없어도 그대로 게시할 수 있으며,
날짜·가격·상품 링크·대장명·연락처·계좌번호·PII를 포함하지 않는다.

#### 초안 1 — 여름의 조용한 길

```text
한여름이 되면
시원한 곳보다 조용한 길이 먼저 생각납니다.

나무 사이로 햇빛이 조금씩 들어오고,
마음에 드는 자리가 있으면 잠깐 멈추는 길이요.

빠르게 많이 보는 날보다
한 곳을 천천히 걷는 날이 오래 남을 때가 있습니다.

오늘은 여러분께도
그런 길 하나를 조용히 건네고 싶었습니다.
```

#### 초안 2 — 천천히 걷는 날

```text
걷다 보면 유난히 발걸음이 느려지는 날이 있습니다.

힘들어서가 아니라
그늘도 보고 바람도 느끼고 싶어서요.

여행은 늘 멀리 가야 기억에 남는 것은 아닌 것 같습니다.

조금 천천히 걸었던 시간이
나중에는 더 선명하게 떠오르기도 하니까요.

여러분은 산길과 물길 중
어느 쪽에서 더 천천히 걷게 되시나요?
```

#### 초안 3 — 일정은 필요할 때

```text
여행 이야기를 읽다가
날짜가 궁금해지는 순간이 있습니다.

그럴 때는 밴드의 일정 탭에서
마음이 가는 여행 이름을 눌러보시면 됩니다.

한꺼번에 다 살펴보지 않으셔도 괜찮습니다.

먼저 가보고 싶은 곳을 만나고,
날짜는 그다음에 천천히 확인해보세요.
```

#### 초안 4 — 오래 남는 장면

```text
여행이 끝난 뒤에는
유명한 장소보다 작은 장면이 더 오래 남기도 합니다.

아침에 마신 따뜻한 차,
걷다가 함께 쉬었던 나무 그늘,
숙소로 돌아오며 본 저녁빛 같은 것들이요.

여러분의 지난 여행에서
지금도 문득 떠오르는 장면이 있으신가요?

짧게 한 가지씩 나눠주셔도 좋겠습니다.
```

#### 초안 5 — 다음에 읽고 싶은 길

```text
다음에는 어떤 길 이야기를 읽고 싶으신가요?

나무 냄새가 좋은 숲길,
걷고 나서 쉬어가는 온천마을,
바람 소리가 가까운 섬길.

정답은 없습니다.

마음이 가는 것 하나만 남겨주시면
앞으로의 글감을 고를 때 참고하겠습니다.
```

### 5.5 선택 사진 규칙

사진은 선택 사항이며, 없으면 본문을 바꾸지 않고 그대로 게시한다.

1. 화면 기준을 통과한 Commons PD·CC0·CC BY 제3자 촬영본
2. 화면 기준과 사용 권한을 통과한 대장 원본
3. 적격 사진이 없으면 텍스트만 게시

- CC BY는 `사진: 저작자 / CC BY 버전 / 원문 URL` 형식으로 크레딧을 적는다.
- CC BY-SA, AI 생성 이미지, Pexels 이미지는 첫 실행에 사용하지 않는다.
- 얼굴 식별이 가능한 사진과 PII가 포함된 이미지는 사용하지 않는다.

## 6. 권한 부족

| 상태 | 처리 | 금지 |
|---|---|---|
| 리더/권한 있는 공동리더 | 파일럿 또는 승인 배치만 실행 | 전수 일괄 저장 |
| 멤버/작성자 아님 | 읽기 감사 후 `permission_denied` | 우회 수정 |
| 수정 버튼 없음 | 중단, 권한 역할 로그인 요청 | 계정 식별 정보 기록 |
| 로그인 만료/2차 인증/CAPTCHA | 사람에게 로그인 재개 요청 | 보안 우회 |
| 브라우저 중단 | 읽기 결과까지 보존 후 중단 | 불완전 상태 추정 |

## 7. 롤백

검증 실패 시 해당 일정의 제목·종료일·본문 첫 줄·공유 옵션을 변경 전 값으로 한 번만 복원한다.
복원 뒤 URL/ID·날짜·댓글 수·참석 수·공유글 상태를 다시 확인한다.

다음은 `rollback_failed`로 기록하고 추가 조작을 중단한다.

- 원래 종료일로 복원되지 않음
- 일정 또는 공유글 URL/ID 변경
- 댓글·참석 숫자 미복구
- 새 공유글 잔존
- 권한·브라우저 장애로 확인 불가

이미 발송된 알림, 삭제된 글·댓글, 외부 검색·캐시는 롤백할 수 없다. 삭제·재생성은 롤백 수단으로
사용하지 않는다.

## 8. 운영 로그와 검증 게이트

`operations/band/TEMPLATE.md`의 `Event remediation` 블록을 사용한다.

### G1 — 개수

- 과거 후속 후보를 현재 미등록 수로 사용하지 않음
- UI ID 감사로 실제 고유 이벤트 수 산출

### G2 — 날짜

- 카페 원문과 reserve 상세 일치
- 불일치면 `date_conflict`

### G3 — 보존

- URL/ID·댓글·참석·공유글 유지
- 예상 밖 알림·재공유 없음

### G4 — 배치

- 파일럿 1건, 이후 최대 3건
- 배치별 검증, 실패 시 중단·1회 롤백

### G5 — 피드

- 신규 일정 공유글 0건
- 결합 관계가 불명인 기존 공유글 삭제 0건
- 2주 여행지 중심 글 5편 유지
- 월간 색인은 첫 2주 뒤 필요성이 확인될 때만 별도 1건

## 9. 메인 세션 체크리스트

1. 브라우저를 복구하고 관리자 탭 하나만 연다.
2. 2026년 8월~2027년 5월을 읽기 전용으로 감사한다.
3. 고유 이벤트 수와 분류별 개수를 확정한다.
4. 가장 먼 미래·댓글 0·참석 0 파일럿 1건을 고른다.
5. 변경 전 `Event remediation` 로그를 완성한다.
6. 대표 출발일 하루로 수정하고 표시·알림·피드·URL·댓글·참석을 검증한다.
7. 통과 시 최대 3건씩 점진 변환하고, 실패 시 즉시 중단·원복한다.
8. 신규 일정은 출발일 하루·본문 전체 기간·공유 끄기를 기본으로 한다.
9. 변환일과 다른 날 2주 콘텐츠 5편을 편성한다.
10. 외부 삭제는 공유글 독립성과 무손실이 입증되기 전까지 하지 않는다.
