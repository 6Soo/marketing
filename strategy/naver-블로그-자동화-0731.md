# 네이버 블로그 자동화 실행안 — 2026-07-31

## 목표 정의

네이버 블로그는 Instagram의 복제물이 아니라 네이버 안의 검색·장문·아카이브 채널입니다.
목표는 “글을 많이 올림”이 아니라 다음 흐름을 검증하는 것입니다.

```text
네이버 검색 발견
  → 여행지 글 읽기
  → 실제 사진·공식 근거로 신뢰
  → foresttour.kr 전체 기록
  → 정확히 맞는 공개 일정이 있을 때만 연결
```

글 자체의 설득 흐름은 아래와 같습니다.

```text
여행지를 발견한다
  → 역사·생활을 이해한다
  → 혼자 찾아갈 수 있는 교통·동선을 얻는다
  → 실제 환승·예약·날씨 변수에서 준비의 수고를 판단한다
  → 같은 여행을 구현한 공개 상품이 있을 때만 숲길여행과 연결한다
```

정보를 감춰 “혼자 못 간다”는 결론을 유도하지 않습니다. 독립 여행에 충분한 정보를 주고도
남는 실제 조율 비용이 상품의 가치가 되게 합니다.

## 자동화 경계

| 단계 | 자동 | 사람 |
|---|---:|---:|
| 원본 digest·사진 권리·출처·태그 검증 | O |  |
| 네이버용 장문 여행 정보 원고 생성 | O | 문장 최종 확인 |
| 현지 사진 다운로드·SHA-256·업로드 순서 | O |  |
| 보이는 WSL SmartEditor 열기 | 사용자 사전 승인 뒤 O | 로그인 |
| SmartEditor 제목·문단·사진 초안 배치 | 사용자 사전 승인 뒤 O | 화면 검수 |
| 공개 |  | O |
| 공개 URL·제목·핵심 본문 실측 | O |  |
| D+3·D+7·D+28 검색 유입 판정 | 반자동 | 결과 해석 |

종료된 글쓰기 API를 대체하는 무인 대량 발행기를 만들지 않습니다. 공식 공유 화면은 500자
링크 스크랩이라 장문 원고에 부적합하므로, 로그인된 WSL의 보이는 SmartEditor에 초안을 배치하고
사람 검수와 명시적 저장·공개를 둡니다.

사용자가 같은 컴퓨터에서 마우스를 쓰는 동안에는 보이는 브라우저를 조작하지 않습니다. 원고 생성,
검색 의도 검증, 사진 다운로드, 테스트와 보고는 WSL 백그라운드에서 수행하고, SmartEditor 열기·
초안 배치·공개 확인은 실행 직전에 사용자 허락을 받습니다.
브라우저를 사용하는 `open`·`stage`·`verify` 명령은 승인 사실을 `--user-approved`로 한 번 더
명시하지 않으면 코드가 실행을 거부합니다.

## 콘텐츠 계약

- 네이버 원고는 `destination-guide-with-practical-access` 계약을 사용합니다.
- 여행지 이야기뿐 아니라 들어가는 법, 현지 이동, 직접 준비하는 동선, 예약 체크리스트,
  실제 준비 난점을 공식 자료와 확인일로 제공합니다.
- 사진은 `photoStatus=verified`만 사용합니다.
- 저작자·라이선스·현지 촬영·Commons 원문 URL을 이미지와 1:1로 유지합니다.
- 독립 여행에 필요한 정보를 일부러 빼거나 불편을 과장하는 문구는 게이트로 차단합니다.
- 공개 일정이 없으면 없다고 씁니다. 내부 기획을 출발 확정으로 바꾸지 않습니다.
- 상품 CTA는 원본 `connectedTour`와 공개 예약 URL이 함께 검증된 경우에만 허용합니다.

## 검색 유입 설계

사도는 동명 검색 의도가 있는 여행지입니다. 제한적으로 확인한 네이버 비로그인 검색 결과에서
`사도섬 여행`은 여수 사도와 신안 12사도 결과가 많이 섞였고, `일본 사도섬 여행`과
`니가타 사도섬 여행`은 일본 사도 결과로 좁혀졌습니다. 검색량의 크기는 네이버 데이터랩
자격정보가 없어 확인하지 못했으므로 추정치로 채우지 않습니다.

- 기둥 글 대표 검색어: `일본 니가타 사도섬 여행`
- 제목과 첫 문단: `일본`·`니가타`를 모두 포함해 동명 지역을 구분
- 지원 질문: 사도섬 가는 법 / 렌터카·버스 / 2박 3일 권역 동선
- 주 2편 이하, 글 사이 최소 3일
- 지원 글마다 신규 공식 출처 2개, 독립 검증 사진 2장, 기둥 글과 본문 중복률 25% 이하
- 같은 대표 검색어를 여러 글에 배정하지 않고 각 글이 독립적인 질문 하나에 답함

정본은 `naver-blog/growth-plan.json`, 집계 결과는 `naver-blog/observations.json`입니다.
`tools/naver-blog-growth.mjs`가 검색어·제목·질문 중복, 지원 글의 조사 증거, 발행 속도와
개인정보 없는 측정 계약을 검증합니다.

첫 지원 글은 `일본 사도섬 가는 법`입니다. `naver-blog/support-drafts.json`의 장문 원고는
니가타역·공항에서 항구로 가는 법, 카페리·제트포일 선택, 온라인 예약, 당일 승선, 수하물과
결항 대응만 깊게 다룹니다. 기둥 글의 금산·슈쿠네기 소개를 잘라 재게시하지 않습니다.

- 본문 4,935자, 기둥 글과 5어절 중복률 1.3%
- 공식 출처 7개 중 기둥 글에 없던 신규 URL 6개
- 기존 기둥 글과 다른 료쓰항 외관·발권 공간 CC BY 사진 2장, 각 3840×2880
- 고정 Commons 리비전과 실제 파일 SHA-256 일치
- 기둥 네이버 글 공개 URL이 검증될 때만 내부 링크를 실제 URL로 바꾸고 발행 준비 상태가 열림

나머지 지원 글 두 편은 기둥 글의 초기 발견 데이터를 보기 전 기계적으로 쓰지 않습니다. 첫 글의
실제 검색 유입이 없는 상태에서 글 수만 늘리는 것은 이 전략의 성공이 아닙니다.

## 1차 실행

1. 사도 1편을 첫 글로 사용합니다.
2. WSL 전용 프로필에 QR 로그인합니다.
3. 생성된 4개 현지 사진과 장문 원고를 SmartEditor에 자동 배치합니다.
4. 문단·모바일 미리보기·출처를 사람이 확인한 뒤 임시저장 또는 공개합니다.
5. 공개 URL을 CLI가 다시 열어 제목·실용 정보·사진 출처·원문 링크 앵커를 확인하고 기록합니다.
6. D+3·D+7·D+28에 `일본 니가타 사도섬 여행`의 발견 여부, 순위 구간, 글 조회,
   검색 유입, foresttour 클릭을 집계합니다.
7. D+7에 발견되지 않으면 발행량을 늘리지 않고 제목·첫 문단·블로그 주제 설정을 먼저 진단합니다.
8. D+28에 유입이 확인된 질문만 다음 여행지 클러스터에 재사용합니다.

## 성공 기준

- P0: 중복 공개 0, 출처 누락 0, 잘못된 일정 연결 0
- 게시 성공: 공개 URL에서 제목·원문 링크·실용 정보 5구간·사진 캡션과 원문을 모두 확인
- 검색 역할: D+7 안에 `일본 니가타 사도섬 여행`으로 실제 발견, D+28에 검색 유입 집계 확인
- 연결 역할: 공개 글의 `foresttour.kr` 링크가 정상이고 내용이 같은 여행지로 이어짐

검색 노출이 없으면 발행 빈도를 올리지 않습니다. 제목·요약의 검색 의도, 블로그 주제 설정,
계정/블로그 기본 정보, 글 품질을 먼저 점검합니다.
