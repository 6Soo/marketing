## 1. 도달이 0인 기계적 원인 (추측 아님)

### (1) 게시물 5건 전부 캐러셀 — 릴스 0건 ★최대 원인★

2026년 인스타에서 **팔로워 5,000명 미만 계정이 비팔로워에게 닿는 사실상 유일한 포맷은 릴스**다.
릴스 평균 도달률 30.81% / 캐러셀 14.45% / 정지 이미지 13.14%인데, 이 비율은 **팔로워 대비**다.
팔로워가 0이면 캐러셀의 14.45%는 0에 곱해진다 — 구조적으로 0이다.

반면 릴스는 팔로워 0이어도 탐색(Explore) 추천 시스템에 진입한다. 협업 필터링으로 우리 계정과
한 번도 상호작용한 적 없는 사용자에게 노출된다. **캐러셀은 이미 아는 사람에게 보여주는 포맷이고,
릴스는 모르는 사람에게 닿는 포맷이다.** 우리는 아는 사람이 0인데 캐러셀만 5번 올렸다.

### (2) 해시태그 전략이 폐기된 메커니즘에 기대고 있다

현재 게시물마다 해시태그 7개. 그런데 **해시태그 팔로우 기능은 폐지됐고**, 검색 노출은 해시태그가
아니라 **캡션 키워드** 기반으로 옮겨갔다. 권장치도 3~5개다.

게다가 붙은 태그 상당수가 검색량이 사실상 0인 초niche 한국어 조합이다:
`#다테야마구로베알펜루트` `#미치노쿠시오카제트레일` `#다라이부네` `#슈쿠네기`.
이 태그들은 "그 단어를 이미 아는 사람"만 찾는다 — **우리 콘텐츠의 전제가 "아직 모르는 곳을
알린다"인데, 아는 사람만 찾을 수 있는 태그를 달고 있다.** 전략과 수단이 정면으로 어긋난다.

### (3) Trial Reels는 우리가 쓸 수 없다

비팔로워에게만 먼저 노출해 반응을 보는 기능이지만 **팔로워 1,000명 이상**이어야 한다.
0명인 지금은 선택지가 아니다. (1,000 도달 후 재검토)

### (4) 산리쿠가 중복 게시됐다 — 실제 결함

`DbMCkYbEsxd`(7/24)와 `DbPkcaIEwSj`(7/26)의 **캡션 SHA-256이 완전히 동일**하다. 같은 글이
이틀 간격으로 두 번 올라갔다. 코드에는 중복 방지 장치(`assertNotDuplicateCaption`, 최근 25건 대조)가
있지만 **웹 UI 수동 게시가 그 게이트를 우회**했다. 중복 콘텐츠는 추천 시스템에서 불리하게 작용한다.

### (5) 2026 랭킹 신호 — 우리가 설계에 반영하지 않은 것

Mosseri가 확인한 배포 신호 3가지: **시청 시간(watch time)**, **도달 대비 좋아요**,
**도달 대비 전송(sends)**. 이 중 **DM 공유(sends)가 신규 도달에 가장 큰 가중치**를 갖는다.
지금 콘텐츠에는 "친구에게 보내고 싶게 만드는 장치"가 없다. 저장 유도는 있지만 공유 유도는 없다.

## 3-A. 훅 재설계 — 구현 완료 (사장 승인 2026-07-29 "릴스 허용. 훅을 훨씬 더 강하게")

### 발견한 치명적 결함: 결정적 첫 0.5초가 검은 화면이었다

시청자는 **1.7초 안에** 계속 볼지 정하고, 알고리즘은 **첫 0.5초**의 반응을 본다.
그런데 구버전 빌더는 `fade=t=in:st=0:d=0.6` — **0.6초 페이드인**이 걸려 있었다.
실측 밝기(YAVG): 첫 프레임 **16**, 0.4초에도 **46**. 가장 중요한 구간을 검은 화면으로 썼다.

| | 개선 전 | 개선 후 |
|---|---|---|
| 첫 프레임 밝기 | **16** (거의 검정) | **65.4** (즉시 최대) |
| 0.5초 구간 | 페이드인 진행 중 | 65.4 → 66.0 안정 |
| 길이 | 25.6초 | **9.4초**(북알프스) / 7.9초(사도) |
| 모션 | 없음(정지 슬라이드) | 펀치인 + 켄번즈(교대) |
| 리듬 | 균등 3.2초 | 훅 1.6s → 급속 컷 3×0.5s → 페이오프 3×1.5s → 아웃트로 1.8s |

### 훅 구조와 근거

1. **페이드인 제거** — 표지 질문이 0프레임부터 최대 밝기로 보인다.
2. **표지 펀치인 줌(1.00→1.06)** — 정지 화면은 '멈춘 콘텐츠'로 읽혀 스크롤을 부른다.
   카드 디자인은 그대로 두고 카메라만 움직인다(비주얼 계약 유지).
3. **1.6초 지점에 급속 컷 3연발 = 패턴 인터럽트** — 이탈 결정 시점(1.7초)과 리듬 변화를
   정확히 겹쳤다. 패턴 인터럽트 계열의 3초 유지율이 **72~84%**로 6개 훅 유형 중 가장 높다
   (커리오시티 갭 65~78%, 직접 질문 58~72%).
4. **이후 느린 켄번즈로 감속** — 급속 컷으로 끌어온 주의를 본문에서 회수한다.
5. **오픈 루프** — 표지 질문을 아웃트로에서 닫는다(카드 문안이 이미 그 구조다).

가장 흔한 실패가 "느린 빌드업"인데, 구버전이 정확히 그것이었다(검은 화면 → 정지 표지 3.2초).

### 4-3. 음악 트랙 확보 — **Pixabay로 확정(사장 승인). 단 파일 수급은 사람 몫이다**

> **2026-07-29 실측: Pixabay는 자동 다운로드가 막힌다.** 음악 페이지가 봇 접근을 차단하고
> (HTTP 403), Pixabay API는 이미지·영상만 다루고 음악을 제공하지 않는다.
> 대안으로 Openverse API(CC 라이선스 검색)를 뒤졌으나 **CC0로 작곡된 음악은 0건**이었고
> (있는 것은 효과음·필드 레코딩), CC-BY 음악은 있으나 **출처 표기가 의무**라
> Pixabay를 고른 이유(표기 불필요)와 어긋난다.
>
> **→ 사장님이 브라우저에서 직접 1개만 받아주시면 된다(2분).** 고르는 기준과 기록 양식은
> `cardnews/assets/music/출처.md`에 정리해 뒀다. 파일을 그 폴더에 두고
> `--music=` 으로 지정하면 즉시 반영된다. 그때까지 빌더는 placeholder 사용 시 경고를 띄운다.


폭넓게 검토한 결과는 `cardnews/docs/인스타-자동게시-음악.md` §3-A 표에 정리했다. 요약:

- **인스타 전용 판 → Meta Sound Collection**(`facebook.com/sound/collection`).
  상업 사용 명시 허용, 출처 표기 불필요. 단 **Meta 플랫폼 밖에서는 못 쓴다.**
- **인스타+유튜브 같은 판 → Pixabay Music.** 상업 사용 허용, **출처 표기 불필요**,
  플랫폼 제약 없음. 유튜브용으로 다시 굽는 이중 작업이 사라진다.
- **⚠ YouTube 오디오 보관함은 인스타에 쓰면 약관 위반이다** — 표준 라이선스가 유튜브 전용이다.
  (이전에 "무료 옵션부터 검토" 하며 이걸 예로 든 것은 **틀린 조언이었다. 정정한다.**)
- 어느 쪽이든 **다운로드 시점의 트랙 페이지·라이선스 문구를 캡처해 보관**한다.
  사진 출처 검증과 같은 원칙 — 나중에 증명할 수 없으면 쓰지 않은 것과 같다.

현재 `placeholder-ambient.wav`는 코드 합성물이라 **법적으로는 지금 게시해도 문제없다.**
완성도만 아쉬우므로, 위 둘 중 하나에서 트랙을 받아 `--music=`으로 지정하면 바로 교체된다.

## 5. 하지 않기로 한 것

- **팔로워 구매·상호 팔로우** — 참여 신호가 오염돼 추천 시스템에서 회복이 어렵다.
- **게시 빈도만 늘리기** — 포맷이 캐러셀인 한 빈도를 늘려도 도달은 0에 머문다.
- **유료 광고** — 순이익률 4% 구조상 오가닉 검증 전 집행하지 않는다(기존 원칙).
- **Trial Reels** — 팔로워 1,000 미만이라 사용 불가.
