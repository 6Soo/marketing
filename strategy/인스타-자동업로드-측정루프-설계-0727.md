## 1. 아키텍처

두 하위 시스템을 **하나의 여행지 편집 단위**(CLAUDE.md 통합 편집 계약)로 묶는다.

```
[카드 HTML] → render.mjs(PNG) → daily-publish(JPEG·스테이징·지문)
     │
     ├─(A) 발행:  API 경로(막히면) ─▶ 검증된 웹 UI 폴백  → permalink
     │                                    │
     │                      ingest(0h, source=graph-api|instagram-ui)
     ▼
[data/activation/<exp>/index.json]
     │
     └─(B) 측정 루프(6h): report→due → collect(graph-api OR instagram-ui) + foresttour-admin
                → coverage 완전(두 소스그룹)만 recorded → learn(완전 체크포인트만) → 다음 여행지 반복
```

### A. 자동 업로드 — "이중 경로 + 동일 산출물" 원칙
API가 막힌 현실을 설계에 내장한다. **두 경로가 같은 스테이징 산출물**(JPEG 9~10장·캡션·manifest·지문)과
**같은 0h 기록 형식**을 쓰게 만들어, API 복구 시 코드 변경 없이 경로만 바뀌게 한다.
- 경로 1(자동): API 정상 → `carousel --publish` → `_publish-result.json` → `ingest`(source=graph-api).
- 경로 2(폴백): API 차단 → 스테이징 아티팩트를 웹 UI로 수동 업로드 → **동일 ingest 명령에 permalink·source=instagram-ui**.
  현재 ingest 도구는 source를 `graph-api`로 하드코딩(`ingest-instagram-publish-result.mjs:38,51`) → 소스 인자화 필요(§2-A2).

### B. 측정 루프 — "부분 추정 금지, 완전 체크포인트만 학습"
이미 구현된 계약을 유지·강화한다.
- coverage 완전 = `measurementSourceGroups`의 **모든 그룹**에 실측 1건 이상
  (`instagram-activation-report.mjs:19-35`). 0h는 예외(그룹 요구 없음).
- 학습기는 완전 체크포인트만 사용(`instagram-activation-learn.mjs:19-32`).
- 활성화 판정 = permalink + `organicInteractions>0` + `story_*_visit>0`
  (`record-instagram-activation.mjs:106-113`).
  ⚠ **자동 graph-api 경로는 `organicInteractions`를 채우지 않는다**(추출 매핑에 없음,
  `collect-instagram-activation-metrics.mjs:43-49`). 따라서 활성화 판정은 **instagram-ui 수동 입력** 또는
  파생 규칙(§2-B2)이 있어야 성립. 이 사실을 수용기준에 명시한다.

   **남은 일: GitHub Actions 시크릿 등록** — 이게 없으면 워크플로에서는 여전히 수집이 실패한다.
   *검증*: 체크포인트 워크플로 foresttour 스텝이 성공, `data/activation/*`에 foresttour-admin 레코드.
3. **[G3] `ACTIVATION_COLLECT_ENABLED=true` 저장소 변수** — G2 완료 + IG 소스(자동 or 수동) 준비 확인 **후에만**.
   *검증*: due 체크포인트가 "Refuse silent" 없이 수집→커밋.
4. **[G4] 공개 IG 신규 게시 보류** — 사도·북알프스 **due 체크포인트(24h/72h/7d) 기록 완료 전** 새 공개 게시 금지(제약).
   *현재 due*: 사도 24h `2026-07-27T18:47:02Z`, 북알프스 24h `2026-07-27T19:15:31Z` — 오늘 도래.
5. **[G5] 스케줄 재가동** — 각 단계 실제 산출물 3회 수동 검수 + photoStatus=verified 후 `daily-cardnews.yml`
   schedule 복구.
6. **[G6] reservation `/api/track` 계약 확인** — `funnelRows[].{source,event,environment,count}` 스키마를
   reservation 리포에서 1회 교차 확인(외부 리포 — 사용자/해당 세션 협조 필요).
