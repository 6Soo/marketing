# 인스타그램 전체 검토 및 개선안 — 2026-07-26

## 결론

콘텐츠 방향은 맞습니다. “여행상품이 아니라 여행지를 소개한다”는 원칙과
`나만 몰랐던 일본` 시리즈는 차별점이 분명합니다. 다만 현재 상태는 **디자인 시안 검토용**이며
실게시 준비 완료 상태는 아닙니다. 가장 큰 이유는 산리쿠 이미지가 모두 현지 사진이 아닌
Pexels 분위기 대역이고, 공개 이미지 호스팅과 Instagram API 운영 계정 연결도 아직 끝나지 않았기
때문입니다.

이번 개선에서 템플릿의 가독성과 저장 가치를 높이고, 캡션·발행 안전장치를 보완했습니다.
현지 사진만 교체하면 같은 템플릿으로 최종 게시물을 다시 렌더할 수 있습니다.

## 1. 콘텐츠 진단

### 잘 잡힌 것

- `나만 몰랐던 일본`은 독자 1인칭의 발견 서사라 계정 정체성으로 쓰기 좋습니다.
- 산리쿠 편은 열차·우는 모래·절벽·정토 해변·부흥 트레일·해녀로 소재 다양성이 좋습니다.
- 가격·박수·대장명·일정 순서를 카드에서 뺀 판단이 브랜드 원칙과 맞습니다.
- 9장 구성은 한 게시물에서 충분한 체류와 저장을 유도할 수 있는 길이입니다.

### 개선한 것

- 표지 문구를 “멈추는 이유”에서 **“느려지는 이유”**로 바꿔 상시 정차처럼 읽히는 과장을 줄였습니다.
- 2장은 표지의 답을 바로 주고, 이후 각 장 하단은 다음 소재를 예고하도록 연결했습니다.
- 마지막 장은 막연한 다음 편 예고 대신 **산리쿠 핵심 5장면 요약**으로 바꿨습니다.
- 캡션은 일정·박수 중심 문장을 덜어내고, 장소 이야기 → 여행 방식 → 저장 → 프로필 확인 순서로
  정리했습니다.
- 해시태그는 10개에서 7개로 줄이고 지역·관심사 중심으로 묶었습니다.

## 2. 카드뉴스 디자인 진단

### 기존 문제

- 사진 위 제목·본문·필기 문구의 위계 차이가 작아 한 덩어리로 보였습니다.
- 표지 본문이 화면 중앙에 떠 있어 사진과 문구가 따로 노는 느낌이 있었습니다.
- 종이 카드가 단색 면에 가까워 필드노트 콘셉트가 충분히 드러나지 않았습니다.
- 마지막 장은 저장 유도 문구만 있고, 실제 저장할 정보가 부족했습니다.
- 현지와 무관한 대역 사진이 일부 카드의 사실성을 훼손했습니다. 특히 열차·절벽 사진은
  산리쿠 장소 증거로 사용할 수 없습니다.

### 반영한 디자인

- 표지 텍스트를 하단 시선축으로 옮기고 짧은 흰색 인덱스 라인을 추가했습니다.
- 내지 하단에 동일한 인덱스 라인과 강화된 스크림을 적용해 시리즈 리듬을 통일했습니다.
- 제목은 명조, 설명은 고딕으로 역할을 분명히 하고 자간·행간·최대 폭을 조정했습니다.
- 워터마크와 페이지 번호를 모바일 안전여백 안으로 옮기고 대비를 높였습니다.
- 종이 카드에 옅은 기록지 가로선과 붉은 세로선을 넣어 `숲길 RECORD`의 필드노트 성격을
  강화했습니다.
- 마지막 장에 번호가 붙은 5개 요약 목록을 넣었습니다.

## 3. 운영·자동화 검토

### P0 — 게시 전 반드시 해결

1. **현지 사진 교체**
   - 현재 `cardnews/photos/sanriku/출처.md`의 모든 사진은 분위기 대역입니다.
   - 표지, 산리쿠 철도, 오스카 해안, 기타야마자키, 조도가하마, 트레일, 고소데 해안의
     실제 촬영 원본으로 바꿔야 합니다.
   - 교체 후 카드 데이터의 `meta.photoStatus`를 `verified`로 변경합니다.
   - 이번 개선으로 `verified`가 아니면 실게시 명령이 중단됩니다.

2. **공개 이미지 호스팅 연결**
   - Instagram API가 읽을 수 있는 공개 JPEG URL이 필요합니다.
   - 현재 워크플로의 “JPEG 공개 배포” 단계는 주석만 있고 실제 배포가 없습니다.

3. **계정 연결**
   - `IG_USER_ID`, `IG_ACCESS_TOKEN`, `PUBLIC_BASE_URL` 설정이 필요합니다.
   - 연결 전에는 `IG_PUBLISH_ENABLED`를 켜지 않습니다.

4. **토큰 갱신 워크플로 보안**
   - `.github/workflows/loop-workflows.yml` 초안은 갱신 응답을 로그에 출력하고 새 토큰을 평문
     아티팩트로 올립니다. 커밋·활성화 전에 반드시 제거해야 합니다.
   - 새 토큰을 자동으로 GitHub Secret에 다시 쓰는 안전한 체계가 준비될 때까지는 수동 갱신이 낫습니다.

### P1 — 첫 게시 전에 권장

- `daily-cardnews.yml`과 별도 루프 워크플로가 같은 발행 책임을 갖지 않도록 발행 스케줄을 하나로
  통합합니다. 두 워크플로에서 `--publish`가 실행되면 중복 게시 위험이 있습니다.
- 첫 3회는 자동 게시 대신 드라이런 JPEG를 사람이 확인한 뒤 수동 게시합니다.
- 실제 계정 데이터가 쌓이기 전의 가상 Insights 값은 전략 판단에 사용하지 않습니다.
- 저장률은 `저장 ÷ 도달`, 프로필 이동률은 `프로필 활동 ÷ 도달`로 동일하게 기록합니다.

## 4. 권장 운영 리듬

- 주 2회 캐러셀: `나만 몰랐던 일본`의 한 장소·한 사실 중심.
- 주 1회 릴스: 현지 영상이 있는 소재만. 카드뉴스를 억지로 영상화하지 않습니다.
- 주 2~3회 스토리: 다음 지역 투표, 현지 사진 한 장, 새 게시물 재소개.
- 월 1회: 저장률 상위 3개 표지 문형과 이탈이 적은 카드 순서를 검토합니다.

처음 4주는 게시량보다 일관성이 중요합니다. 캐러셀 8편을 채워 프로필 첫 화면만 봐도
“가이드북 밖 일본을 기록하는 계정”이라는 인상이 생기게 하는 것을 1차 목표로 둡니다.
