# reserve.foresttour.kr 시니어 예약 전환 개선 계획

## 1. 결론

현재 `/admin/traffic`의 `예약 완료 0`은 상품 관심이 없다는 증거가 아니다.
현 구조에서는 다음 세 가지를 구분할 수 없다.

1. 배너나 모집글을 눌렀지만 출처가 끊긴 경우
2. 예약 화면에 들어온 뒤 14단계 중간에서 이탈한 경우
3. 카페 댓글·전화로 신청해 온라인 완료 이벤트가 없는 경우

따라서 첫 작업은 CTA 문구 변경이 아니라 **측정 가능한 퍼널 만들기**다.
그다음 예약을 `관심 접수`와 `출발 정보 등록`으로 분리한다.

## 2. 현재 구조에서 확인된 문제

### 측정 문제

- 집계 이벤트는 예약 화면 진입과 최종 완료뿐이라 중간 이탈 위치를 모른다.
- `?from=`이 없으면 첫 화면에서만 카페 리퍼러를 인식하고 다음 내부 이동에서 출처가 끊길 수 있다.
- 전체공지와 모집글 링크에는 `?from=notice`, `?from=post`가 일관되게 붙어 있지 않다.
- 온라인 예약 완료만 보면 기존 댓글·전화 신청이 실패로 보인다.
- 모바일/PC, 다음 카페 앱/모바일 브라우저를 구분하지 않는다.

### 행동·UX 문제

- 카페 공지는 `3분, 성함과 연락처`라고 설명하지만 실제 해외여행 예약은 사실상 13~14개 화면이다.
- 관심 직후 주민등록번호 13자리, 여권, 비상연락처, 결제 방식 등을 요구한다.
- 비회원은 `함께 가는 카페 회원`을 입력해야 다음으로 진행할 수 있어 지인 없이 유입된 신규 회원이 막힌다.
- 계좌 안내가 서버 접수보다 먼저 나온다. 사용자가 은행 앱으로 전환해 페이지가 새로 열리면 입력 상태가 사라질 수 있다.
- `예약하기`가 상담이나 좌석 확인이 아니라 즉시 계약·결제처럼 느껴질 수 있다.
- 다음 카페와 예약 도우미의 도메인·화면·용어가 달라 운영 주체에 대한 신뢰가 끊길 수 있다.

## 3. 시니어 행동에 대한 해석

시니어가 모바일을 사용하지 못하는 것이 핵심 문제가 아니다.
한국 시니어 연구에서 더 강하게 나타나는 장벽은 다음과 같다.

- 여행 앱 고유의 메뉴·용어·인터페이스를 이해하는 부담
- 한 번에 많은 결정을 요구하는 인지부하
- 주민번호·여권·결제 정보에 대한 개인정보·사기 우려
- 작은 글씨·작은 터치 영역·예상 밖 화면 전환
- 문제가 생겼을 때 도움을 받을 수 있는 사람과 방법의 불명확성

숲길여행 기존 회원은 카페 글 → 댓글/전화 → 대장과 관계 확인 → 신청에 익숙하다.
현재 예약 화면은 이 신뢰 확인 단계를 건너뛰고 여행 계약 정보를 먼저 요구한다.

## 4. 목표 퍼널

### 1단계 — 발견·신뢰

`m.cafe.daum.net/sixsungwon`의 원본 최신글·댓글 습관을 유지한다.

- 큰 글씨로 일정 보기
- 카페 원문·댓글로 돌아가기
- 숲길여행 직접 운영 표시
- 대장 이름·연락처·후기·취소/환불 핵심

### 2단계 — 관심 접수

모바일에서 두 경로를 동등하게 제공한다.

#### 직접 신청하기

- 선택 여행 자동 입력
- 이름
- 휴대전화
- 인원
- 개인정보 수집 최소 동의

버튼은 `예약 확정`이 아니라 `좌석 확인 요청` 또는 `참가 의사 접수`로 표현한다.

#### 직원이 전화로 도와드리기

- 이름
- 휴대전화
- 통화 희망 시간

`예약 확정 아님`, `비용 없음`, `숲길여행 직원이 연락`을 명시한다.
전화 선호를 전제하지 않고 직접 신청과 실제 전환을 비교한다.

### 3단계 — 담당 확인

- 접수 완료 메시지와 예상 연락 시간을 안내한다.
- 담당자가 좌석·난이도·항공·객실·비용을 확인한다.
- 기존 카페 닉네임이나 소개자 정보는 선택값으로만 받는다.

### 4단계 — 출발 정보 등록

참가 의사가 확인된 사람에게만 별도 링크로 요청한다.

- 주민등록번호
- 영문명·여권
- 동행자
- 비상연락처
- 보험
- 결제·예약금

한 번에 모두 요구하지 않고 저장·재개가 가능해야 한다.

## 5. 계측 설계

개인 식별정보를 분석 이벤트에 넣지 않고, 세션당 단계 이벤트를 한 번만 집계한다.

### 필수 이벤트

| 구간 | 이벤트 |
|---|---|
| 카페 | 배너 노출, 배너 클릭, 공지 클릭, 모집글 클릭 |
| 상세 | 상세 도달, 카페 원문 복귀, 댓글 보기 |
| 접수 | CTA 노출, 직접 신청 시작, 통화 요청 시작 |
| 폼 | 단계 보기, 단계 완료, 검증 오류, 뒤로가기, 도움 클릭 |
| 완료 | 관심 접수 완료, 통화 요청 완료, 출발 정보 완료 |
| 운영 | 통화 성공, 좌석 확인, 예약금 입금, 최종 예약 |

### 필수 분류

- 유입: `banner`, `notice`, `post`, `cafe-ref`, `direct`
- 기기: mobile / desktop
- 환경: 다음 카페 앱 / 모바일 브라우저 / 기타
- 대상: 기존 회원 / 신규 회원 / 알 수 없음
- 경로: 직접 신청 / 직원 도움 / 기존 댓글·전화

### 통계 화면 개선

`/admin/traffic`은 단순 이벤트 합계가 아니라 다음을 보여줘야 한다.

1. 유입별 모바일 퍼널
2. 단계별 최대 이탈
3. 직접 신청과 직원 도움의 완료율
4. 관심 접수 → 통화 성공 → 예약금 입금
5. 온라인·댓글·전화 신청의 전체 합계

## 6. 실행 순서

### P0 — 측정과 구조적 막힘 제거

1. 전체공지·모집글·배너 링크에 `?from=notice|post|banner`를 일관되게 적용
2. 내부 이동에서도 최초 source를 유지
3. 모바일 환경과 예약 단계 이벤트 추가
4. 비회원 소개자 필수 제거
5. 은행 앱 전환 전에 접수 내용을 서버에 임시 저장
6. 공지의 `3분` 설명과 실제 접수 범위를 일치

### P1 — 간단 접수 실험

1. 기존 14단계는 유지하되 일부 게시판·일부 링크에서만 간단 접수 제공
2. `직접 신청`과 `직원이 전화로 도움`을 동등하게 배치
3. 기존 댓글·전화 경로도 제거하지 않음
4. 2주 동안 접수 완료·통화 성공·예약금 입금을 비교

### P2 — 출발 정보 분리

1. 관심 접수 후 별도 링크로 민감 정보 수집
2. 기존 고객은 안전한 본인 확인 후 저장 정보 재사용
3. 단계 저장·재개와 명확한 진행 상태 제공
4. 제출 전 요약·수정, 제출 후 후속 일정 안내

### P3 — 카페 모바일 이용률 개선과 통합

1. 기존 회원용 `보기 편하게` 공지
2. 신규 회원용 `처음 오셨나요?` 안내
3. 모집 중·곧 출발·후기만 단순하게 연결
4. 검증된 기능만 더 많은 게시판과 회원에게 확대

## 7. 실험 안전장치

- 다음 카페의 최신글·댓글·전화 동선은 변경하지 않는다.
- 기존 대문 아이템이나 게시판을 삭제하지 않는다.
- 첫 실험은 게시판 1~2개 또는 링크 일부에서만 한다.
- 예약 완료 수 하나만으로 성공을 판단하지 않는다.
- 문의 증가, 원본 카페 복귀 증가, 오류 증가를 함께 본다.
- 민감 정보 수집은 관심 접수 이후로 미루되 여행업 운영에 필요한 최종 정보는 누락하지 않는다.
- 전화 경로가 더 낫다고 가정하지 않고 실제 예약금까지 비교한다.

## 8. 의사결정 지표

### 1차

- 모바일 상세 도달 → 관심 접수 시작
- 관심 접수 시작 → 완료
- 단계별 이탈과 오류
- 통화 요청 → 실제 통화 성공

### 2차

- 관심 접수 → 좌석 확인
- 좌석 확인 → 예약금 입금
- 예약금 입금 → 최종 출발 정보 완료
- 기존 회원과 신규 회원의 7일·30일 재방문

### 가드레일

- 전화·문자 문의의 반복 질문 증가
- 잘못된 여행·인원 접수
- 개인정보 관련 문의·불안
- 기존 댓글 신청 감소 대비 전체 접수 감소
- 모바일 뒤로가기·원본 카페 복귀 급증

## 9. 현재 판단

가장 먼저 구현할 것은 디자인 전면 변경이 아니다.

1. 모바일 퍼널 계측
2. 비회원 소개자 막힘 제거
3. 관심 접수와 출발 정보 분리
4. 직접 신청과 직원 도움의 병렬 실험

이 네 가지가 완료되기 전에는 배너의 효과나 시니어의 구매 의지를 정확히 판단할 수 없다.
